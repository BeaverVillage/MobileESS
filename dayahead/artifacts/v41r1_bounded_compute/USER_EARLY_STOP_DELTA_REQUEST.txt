# ============================================================
# 1. 30 MINUTES IS A HARD CAP, NOT A TARGET
# ============================================================

Keep:

POLICY_DAY_TOTAL_OPTIMIZATION_BUDGET = 30 minutes


Interpret this as:

MAXIMUM wall-clock optimization time

NOT:

"always run for 30 minutes."


The solver/F&O procedure may terminate substantially earlier when
the stage-specific convergence conditions below are satisfied.


Fresh OpenDSS and Actual replay remain outside this optimization
budget.


# ============================================================
# 2. SHARED BUDGET ACROSS P1-P5
# ============================================================

The same policy-day timer is shared across all lexicographic stages.


Require:

T_P1 + T_P2 + T_P3 + T_P4 + T_P5 <= 30 min


Do NOT reset a new 30-minute timer at each stage.


Unused time rolls forward to later stages.


# ============================================================
# 3. STAGE GUARDS
# ============================================================

Add soft stage guards to prevent one objective from consuming the
entire policy-day budget.


Initial guards:

P1_SOFT_GUARD = 16 minutes
P2_SOFT_GUARD = 8 minutes
P3_SOFT_GUARD = 3 minutes
P4_SOFT_GUARD = 2 minutes
P5_SOFT_GUARD = 1 minute


These sum to the 30-minute hard cap.


Important:

These are COMPUTE GUARDS, not scientific limits.


If P1 ends in 9 minutes:

the unused 7 minutes remain available to later stages.


Do not artificially hold a later stage to its nominal guard when
significant shared budget remains.


The 30-minute policy-day hard cap remains absolute.


# ============================================================
# 4. DEFINE A SWEEP EXPLICITLY
# ============================================================

A "sweep" is one deterministic traversal of the F&O neighborhood
schedule for the current objective stage.


The schedule must include the existing neighborhood families:

- electrical-critical
- IDC block
- RUNNING migration
- PENDING relocation
- low-visit / coverage / diversification families


The exact ordering may depend on the current objective priority,
but no authoritative candidate is permanently removed.


Track separately for each objective stage:

STAGE_CANDIDATE_VISIT_COUNT
STAGE_UNIQUE_CANDIDATES_OPENED
STAGE_COVERAGE_FRACTION
STAGE_SWEEP_ID


Do not rely only on the global all-stage coverage counter.


We need to know what was actually explored during P1, P2, etc.


# ============================================================
# 5. OBJECTIVE IMPROVEMENT MUST USE RECOMPUTED VALUES
# ============================================================

Do NOT accept solver raw floating-point objective changes as
scientific improvement.


For every proposed incumbent:

1. materialize the actual job-level decision
2. recompute all relevant physical trajectories
3. recompute the objective independently
4. validate all constraints
5. compare against the currently accepted incumbent


Use the already validated numerical objective tolerance.


Do NOT silently loosen the physical feasibility tolerance.


A change such as ~1e-10 caused by floating-point noise must NOT reset
the stagnation logic.


Define conceptually:

MATERIAL_IMPROVEMENT =
    recomputed_new_objective
    <
    recomputed_current_objective
    - validated_objective_tolerance


If not:

NO_MATERIAL_IMPROVEMENT


# ============================================================
# 6. P1 EARLY-STOPPING LOGIC
# ============================================================

P1 remains:

minimize rho_max


At the beginning of every P1 sweep:

recompute the current incumbent's:

- maximum-loading branch
- phase
- time
- near-binding electrical set


Use that information only to PRIORITIZE the first neighborhoods.


Do NOT prune candidates using sensitivity.


For an opened job, preserve its complete authoritative feasible
destination set.


P1 algorithm:


START from verified feasible incumbent.


Run NORMAL SWEEP.


If at least one MATERIAL P1 IMPROVEMENT occurs during the sweep:

- accept the best validated incumbent
- recompute the new critical branch/phase/time
- reset the stagnation state
- begin another normal sweep if P1 time remains


If one completed normal sweep yields:

NO MATERIAL P1 IMPROVEMENT


then run exactly ONE additional:

OVERLAP / DIVERSIFICATION SWEEP


The diversification sweep must:

- use overlapping neighborhoods
- emphasize low-visit decisions
- include decisions that were not central to the current critical line
- permit coupled reallocations that may indirectly free GPU/rack/WAN
  capacity


If the diversification sweep also yields:

NO MATERIAL P1 IMPROVEMENT


then:

EARLY STOP P1

and lock the accepted P1 incumbent.


Do NOT continue repeating identical no-improvement sweeps merely
because the 30-minute policy-day timer has time remaining.


# ============================================================
# 7. P1 SOFT-GUARD CONDITION
# ============================================================

If P1 reaches its approximately 16-minute soft guard before the above
stagnation sequence completes:

do not blindly continue until 30 minutes.


At the guard:

- preserve best validated P1 incumbent
- record current stage coverage
- record whether a full sweep completed
- record whether diversification completed
- record remaining candidate visit state
- move to P2 unless a currently running short neighborhood is needed
  to close an atomic checkpoint


No candidate is classified as pruned merely because the compute guard
expired.


Classify such candidates as:

NOT_VISITED_WITHIN_P1_COMPUTE_BUDGET


# ============================================================
# 8. P1 LOCK
# ============================================================

After P1 terminates:

P1 <= P1_ACCEPTED + existing numerical tolerance


P2 must not degrade the accepted P1 solution.


Do NOT use:

The optimization-gap concept does not permit degradation of the
accepted lexicographically superior incumbent.

# ============================================================
# 13. DO NOT USE "N CONSECUTIVE FAILED NEIGHBORHOODS" ALONE
# ============================================================

Do NOT implement:

"stop after 10 failed neighborhoods"

as the sole convergence rule.


That could stop when only a small fraction of the authoritative
candidate universe was examined.


Primary convergence evidence must be:

- sweep completion / coverage
- no material improvement
- one diversification attempt
- stage guard / policy-day hard cap


Consecutive no-improvement neighborhood count may be logged as
diagnostic information only.


# ============================================================
# 14. COVERAGE IS NOT THE SAME AS OPTIMALITY
# ============================================================

Do NOT claim:

100% candidate coverage == global optimality


It does not.


Coverage only means every authoritative candidate decision was opened
at least once within the F&O neighborhood schedule.


Persist:

- coverage fraction
- sweep count
- accepted improvements
- objective trajectory
- whether diversification occurred
- termination reason


Use accurate terminology:

F&O convergence / bounded-compute termination

not:

global optimum


unless separately proven.


# ============================================================
# 15. IMPROVEMENT RESETS THE STAGNATION STATE
# ============================================================

Whenever a MATERIAL objective improvement is accepted:

- set incumbent = new solution
- recompute objective-specific structure
- recompute critical electrical point where relevant
- begin a fresh sweep
- reset no-improvement state


This is necessary because the active bottleneck can move.


Example for P1:

old:
line L10 / phase A / 18:00

after relocation:

new:
line L27 / phase C / 20:15


The next F&O sweep must be based on the new incumbent,
not the old critical set.


# ============================================================
# 16. DIVERSIFICATION DOES NOT MEAN RANDOMNESS
# ============================================================

Keep deterministic reproducibility.


Diversification may use:

- low-visit candidates
- overlapping IDC blocks
- overlapping time windows
- coupled source/destination blocks
- stale/fixed decisions not opened recently


Do NOT use nondeterministic random candidate sampling unless an
explicit frozen seed and reproducibility contract already exists.


Prefer deterministic ordering.
