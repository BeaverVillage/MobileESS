# 4. IN-DAY SERVICE ACCOUNTING

For the 24-hour optimization, only the overlap with [0,H) contributes
to Day-D AIDC occupancy/power/grid quantities.


Define:

IN_DAY_SLOTS_j(s_j)
=
max(
    0,
    min(d_j, H - s_j)
)


for jobs starting within Day D.


Equivalently:

IN_DAY_END_j
=
min(s_j + d_j, H)


A job scheduled:

20:00 -> planned duration 11 h

therefore contributes only:

20:00 -> 24:00

to Day-D AIDC/grid calculation.


But its full duration remains 11 h in the job ledger.



# 5. TERMINAL RESIDUAL ACCOUNTING

Define a scalar terminal residual for every relevant PENDING job:

TERMINAL_REMAINING_SLOTS_j(s_j)
=
max(
    0,
    s_j + d_j - H
)


This is NOT a post-H simulation.

It is only an accounting quantity describing how much planned
service lies beyond the independent daily horizon.


Require exact identity:

d_j
=
IN_DAY_SLOTS_j
+
TERMINAL_REMAINING_SLOTS_j


for every selected PENDING job.

# 7. CORE ANTI-DUMPING TERMINAL CONSTRAINT

<=

# 8. INTERPRETATION OF THE TERMINAL CONSTRAINT

Example:

reference:
start = 18:00
duration = 11 h

then:

reference in-day service = 6 h
reference terminal residual = 5 h


Alternative start = 16:00:

terminal residual = 3 h

3 <= 5
PASS

terminal residual = 4 h

4 <= 5
PASS


Alternative start = 20:00:

terminal residual = 7 h

7 > 5
FAIL


Therefore:

cross-midnight jobs CAN move,

but they cannot exploit the horizon by pushing additional service
outside Day D.
