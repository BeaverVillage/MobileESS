## 4. Target와 데이터 인과성

기존 target의 공통 기준:

w_j = gpus_requested_j × (observed_end_j - observed_start_j) / 3600
Y_window = sum(w_j for jobs whose submit_time is inside the window)

이는:
- 신규 유입 작업의 전체 lifetime GPU-work
- 실제 GPU 점유량이나 전력부하가 아님
- 여유용량 자체가 아님
- window 안에서 반드시 완료해야 하는 작업량도 아님

기존 cohort/단위/zero/missing 처리와 GPU 수량 authority를 유지하세요.
GPU 결측을 0 또는 nodes×4로 임의 대체하지 마세요.
12개 synthetic AIDC 배분을 12개의 독립 실측 학습시계열처럼 늘리지 마세요.

모든 예측은 D−1 18:00 fixed AEST, UTC+10 기준입니다.
다음날 00시까지의 6시간 lead gap도 유지하세요.

미래 Job의 GPU request/runtime/count/partition/QoS를
해당 issue의 predictor에 넣지 마세요.
현재 미완료 Job의 최종 runtime도 사용할 수 없습니다.

feature에는 issue까지 관측된 제출 정보와
성숙한 과거 GPU-work 및 maturity mask/age만 사용하세요.

원래 full-day maturity 규칙:
max(target_day_end, target_label_available_at) < issue_time

를 기본으로 유지하세요.
새로운 maturity 규칙을 시험하려면 별도 실험으로 분리하고
기존 baseline에 조용히 적용하지 마세요.

raw archive의 partition 월과 submit 월이 다를 수 있으므로
파일명 월만 보고 자료를 누락시키지 마세요.


## 5. 먼저 공정한 H4 모델 교체 실험

첫 번째 실험은 target/horizon/interface를 바꾸지 않고
기존 H4, 81개 window/day에서 모델 차이만 평가합니다.

필수 비교군:

F0: 기존 frozen CC4 — 기존 85% 보정 그대로, 역사적 reference
F1: 동일 데이터의 LightGBM Q90 + 90% 보정 — 공정한 nominal-90 기준
F2: 소형 TFT 기반 대체 후보
F3: DeepAR 기반 대체 후보

기존 seasonal empirical quantile도 값싼 기준으로 포함하세요.

TFT/DeepAR를 처음 시험하는 모델 또는 자동으로 우수한 모델이라고
표현하지 마세요. 이전 R3 구현·결과와 이번 변경점을 명시하세요.

새 모델을 개발한다는 요청을 cap/quantile 변경만으로 대체하지 마세요.
최소한 신경망 대체 후보의 실제 학습과 검증을 수행하세요.

1차 비교에서는 학습기간·target·사용 가능한 정보·nominal coverage를 맞춥니다.
신경망이 raw sequence를 쓰고 tree가 요약 특징만 쓰는 경우,
그 차이를 명시하고 동일한 정보원/성숙 경계를 보장하세요.

처음부터 큰 모델이나 무제한 hyperparameter sweep을 실행하지 마세요.
모델별 소수의 설정을 development에서 비교하고,
선택 설정은 최소 3개 고정 seed로 반복 평가하세요.
좋은 seed만 골라 보고하지 마세요.

모든 후보의 postprocessing/calibration 계산 예산과 선택 규칙을
실행 전에 EXPERIMENT_PROTOCOL.json에 기록하세요.

새 신경망에만 최근 자료를 주지 말고,
동일 갱신 규칙의 LightGBM comparator를 함께 둡니다.

refit cadence와 학습 설정은 development에서 확정하세요.
실제 각 issue의 training membership/date range/N을 저장하세요.

현재 raw 데이터의 가용 기간을 먼저 확인하고,
존재하지 않는 학습기간이나 새로운 holdout을 임의로 가정하지 마세요.


## 7. 시간창 실험은 분리해서 수행

H4 모델 비교 이후, 유망한 최대 두 모델과 LightGBM 기준에 대해:

H = 1, 2, 4, 8 hours

를 비교하세요.
기존 H1/H4/H8/H24 연구는 historical reference로 보존합니다.

공통 15분 submit-bin GPU-work에서 각 합계 target을 생성하고,
같은 issue와 같은 날짜 split을 사용하세요.

15분 stride, 하루 안에서 완결되는 window라면:
H1 = 93 windows/day
H2 = 89
H4 = 81
H8 = 65

가 되는지 검증하세요.
정시 시작 24개 H1만 별도 평가한다면 다른 표본이라고 표시하세요.

각 horizon은 그 horizon의 기준모델과 비교합니다.
긴 창의 raw loss와 짧은 창의 raw loss를 그대로 비교해 우승자를 고르거나,
zero 비율이 높아 coverage가 높아진 것을 성능 개선으로 해석하지 마세요.

1시간 Q90 네 개를 합쳐 4시간 Q90이라고 하지 마세요.
합계 target을 직접 예측하거나,
시간적 의존성을 보존한 예측 경로 표본에서 합계 분위수를 계산하세요.

이번 작업에서는 기존 P2/reserve optimizer를 변경하지 않습니다.
새 시간창의 optimizer 연결은 결과 확인 후 별도 검토합니다.


## 8. 90% 목표와 calibration

주목표:
uncapped one-sided predictive coverage ≈ 90%

현재 May의 기존 H4 target/cap 조건에서는
physical-cap oracle coverage=85.9418558343%입니다.
따라서 actionable coverage >=90%를 성공조건으로 요구하지 마세요.

다음을 반드시 분리하세요.
- raw model quantile
- calibrated uncapped forecast
- historical/physical cap 적용 후 값
- 실제 확보된 reserve

기존 85% CC4보다 90% 후보가 coverage가 높다는 이유만으로
모델 성능이 개선됐다고 하지 마세요.
동일한 90% 보정 기준의 LightGBM과 비교해야 합니다.

Calibration에는 chronological out-of-sample residual만 사용하세요.
TRAIN fitted residual, 아직 성숙하지 않은 label,
미래 평가기간 residual을 미리 사용하지 마세요.

상시 capacity cap 또는 큰 상수를 예측하는 trivial baseline도 포함해,
단순 과대예측으로 coverage만 높이는 후보를 구분하세요.

0값이 많은 target에서는 전체 coverage와 양수 coverage의 관계를 확인해
동시에 달성 불가능한 gate를 만들지 마세요.
과거 R5의 zero-inflation gate 문제를 반복하지 마세요.
