# 사용자 정정: K48만 재사용, Joint 새900초를 0부터

직접 사용자 지시 `900초 예산 처음부터 0초부터 줘야지.. 반영해.`를 반영했다. 앞선 사용량 차감 정책을 대체해 May01/May02 B2의 attempt003은 완료 K48 결과·Binary 행렬만 가져오고 Joint는 새 독립900초 실험으로 시작한다. 단일 호출 cap300초, Threads1 및 기존10초 반환 여유를 유지한다. 첫 새300초 호출 후 남은 Joint 예산은600초다. 기존 약561초와 이전 Attempt의 새 호출 사용량을 차감하지 않는다.

기존 Native 원장/Raw와 종료 결과는 수정하거나 삭제하지 않는다. 새 운영 정책과 Source SHA, 별도 Permit, Attempt003 및 체크포인트에 새 실험을 명시한다. 같은 과학적 행렬/물리 Case SHA를 유지하되 실행 정책 SHA와 Attempt는 구분한다. 원장 초기화가 아니라 사용자가 승인한 새 Joint 실험이다. 완료 K48의 약300초 결과는 그대로 보존하며 재계산0회다. 이 일회 전환은 지정한 두 날짜의 attempt003에만 적용해 일반 재개가 자동으로 새 예산을 부여하지 않게 한다.

활성 명령은 `python -m v44.fresh900 --resume`다. B2 2-worker 우선 후 Main1 날짜별 B0→B1→B3를 유지하며 나머지 새 날짜의 Joint도 원래 계획대로900초/호출cap300초다. 새 예산0초·900초 확인 및 이전 원장 무변경 테스트를 포함해193 PASS/0 FAIL이다. Actual/Fresh 또는 K48 추가 계산 검증은 수행하지 않았다.
