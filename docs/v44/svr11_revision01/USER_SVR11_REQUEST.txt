# V44 수정 지시 — 기존 V42 SVR11 최종 장비·전압 모델·AUTO/TIME 제어를 V44 Planning/Actual에 정식 이식

현재 [PR #233](https://github.com/BeaverVillage/MobileESS/pull/233)의 V44 작업을 이어서 진행하라.

**이번 지시에서는 V44에 기존 SVR11 장비 11뱅크를 반드시 추가한다. 새로운 SVR 배치나 제어 알고리즘을 설계하지 말고, GitHub에 남아 있는 기존 V42 SVR11 최종 코드를 재사용하라.**

SVR11 추가는 사용자가 승인한 명시적인 물리 모델 변경이다. 이전 V44의 7-RegControl 동결 조건보다 본 지시를 우선한다.

다만 AIDC·MESS 최적화 알고리즘, 목적함수, 정수 제약, 경로 탐색, K48·Beam·Joint MILP, Known/Unknown 제어 정책은 그대로 유지한다.

**최우선 원칙: Planning과 Actual은 동일한 SVR11 장비를 사용하지만, 전력망 입력·전압 응답·탭 상태·제어 큐는 서로 독립적으로 시뮬레이션해야 한다.**

## 2. 정확한 SVR11 장비 구성

기존 11뱅크를 전부 설치한다.

1. STA01
2. STA06
3. STA08
4. BUS83
5. BUS79
6. BUS108
7. BUS50
8. BUS82
9. BUS48
10. BUS86
11. BUS62

정확한 Cut Element, Cut Terminal, Sensed Bus, 변압기 Rating, 원격 PT 비율은 Epoch12 `SCENARIO.json`의 값을 그대로 따른다.

**특히 BUS82는 Epoch12에서 수정한 최종 구조를 반드시 사용한다.**

- 기존 `Line.l82`의 상류 측
- `cut_terminal=1`
- `original_bus_spec=81.1.2.3`
- `upstream_new_bus=svr_bus82_line_input`
- `sensed_bus=82`

이전 BUS82 배치로 되돌리지 마라.

### 하드웨어 조건

- 기존 IEEE123 RegControl: 7개 유지
- 추가 SVR: 11뱅크
- 추가 RegControl: 상별 33개
- 최종 RegControl: **40개**
- 기존 Capacitor: 4개, Fixed ON
- CapControl: 0개
- DSTATCOM: 0개
- 추가 Q-injection 장치: 0개
- 탭 최적화 변수: 0개

기존 Original 7개의 설정은 유지한다.

신규 11뱅크는 기존 Epoch12의 Native OpenDSS RegControl 설정을 그대로 사용한다.

- VReg 120 V
- Band 2 V
- Delay 30초
- TapDelay 2초
- MaxTapChange 1
- Tap 범위 0.9~1.1
- 32 Tap Steps
- Remote Sensing 및 PT/CT 비율 원본 유지

기존 Line/Transformer의 원래 Impedance, Length, NormalAmps, Winding kVA 및 연결 물리 조건은 유지한다.

새 SVR도 실제 유한 정격을 가진 변압기로 모델링하고, 정격을 무한대로 만들거나 임의 Bus Voltage Setter로 대체하지 마라.

**SVR은 실제 탭을 변경하는 직렬 전압조정 장치다. 임의의 무효전력 주입 장치가 아니다.**

## 3. Planning — Forecast 상태에서 SVR의 자동 응답을 반영

Planning에서는 실제 미래 부하를 사용하지 않는다.

각 날짜 D의 D-1 18:00 Issue 시점에 이용 가능한 예측 정보로 전력망 모델을 생성한다.

사용할 입력:

- Forecast 수요·PV
- AIDC Known 계획 및 CC4 Forecast
- 기존 Runtime 예측
- 기존 MESS P/Q 제어변수
- Forecast 교통·이동 정보
- 해당 날짜의 Source 초기 조건

### 반드시 기존 SVR11 Forecast 모델 생성 코드를 재사용하라

`v42_svr11/model.py::generate`

`v42_svr11/ldc_interval.py`

`v42_voltage_control/timecontrol.py::CommonClock`

이 함수들의 실제 호출 경로와 Source SHA를 확인하고 V44에서 재사용하라.

기존 SVR11 모델은 예측 입력으로 OpenDSS를 실행하여 자동 탭 응답을 반영한 전압·전류·선로 P/Q 민감도를 생성한다.

다음 원칙을 유지한다.

1. SVR11이 설치된 전력망을 Forecast용 OpenDSS Context에 구성한다.
2. Forecast 입력으로 시간순 Native AUTO/TIME 조류를 계산한다.
3. 이전 시간의 탭 상태와 Native Queue에 따른 영향을 반영한다.
4. 민감도를 생성하는 각 독립 Probe에는 동일한 Forecast Prefix를 재생한다.
5. 해당 시간의 제어변수에만 원래 방식으로 Perturbation을 부여한다.
6. 기존 Signed Response·LDC Interval 모델을 사용한다.
7. 해당 날짜의 새 전압·전류·선로 P/Q 계수를 생성한다.
8. 기존 AIDC/MESS 최적화 모델에 해당 계수를 공급한다.

### Planning에서 금지할 사항

- 미래 Actual 수요·PV 사용
- 미래 Unknown 실제 도착정보 사용
- Actual의 RegControl Tap 읽기
- Actual의 Native Control Queue 읽기
- 이전 7-RegControl 계수 재사용
- 이전 SVR 장비 버전의 계수를 새 설비 계수로 승격
- Tap을 MILP 결정변수로 추가
- Day-ahead에서 Tap 경로를 강제로 지정

최적화 대상은 기존 AIDC Workload와 MESS 이동·P/Q/SOC다.

**SVR Tap은 Forecast 상태에 반응하는 OpenDSS 자동제어의 결과이지 새로운 최적화변수가 아니다.**

기존 Epoch12의 LDC Deadband Interval 및 Fixed Capacitor 전압 의존성 보정을 유지한다.

선형 민감도 모델은 국소 근사이며, 비선형 AC 전체 안전성을 보증하지 않는다는 기존 제한도 유지한다.

## 4. Actual — 실제 상태에 따라 40개 RegControl이 독립적으로 동작

Actual에서는 Planning 시뮬레이션의 Tap 상태를 복사하지 마라.

**새로운 OpenDSS Context를 원본 Source Initial State에서 독립적으로 구성하고, 동일한 SVR11을 설치하라.**

Planning과 Actual의 장비 구성은 동일하지만 엔진 인스턴스, 초기화 영수증, Native Queue, Tap History는 독립적이어야 한다.

기존 코드에서 다음을 적극 재사용한다.

- `v42_svr11/initial_context.py`
- `v42_svr11/operations.py`
- `v42_voltage_control/integration.py::scenario_scope`
- `v42_voltage_control/timecontrol.py::CommonClock`
- `v42_voltage_control/isolation.py`

### Actual 입력

시간별 실제 관측 상태를 반영한다.

- 실제 AEMO 수요
- 실제 PV
- 실제 기상
- 실제 Job 도착·종료
- 실제 AIDC GPU 점유
- 관측 Overrun
- 실제 FCFS 또는 Known/Unknown 실행 결과
- Planning에서 동결된 MESS 이동경로 및 P/Q
- 현재 실제 RegControl Tap 및 Native Queue

각 제어시각에서 실제 GPU 점유에 따라 원본 C1 전력모델로 AIDC P/Q를 재계산한다.

B0/B2는 기존 FCFS를 사용하고, B1/B3는 현재 V44 Known/Unknown Actual 정책을 유지한다.

### SVR 실제 제어 순서

각 15분 구간에서:

1. 현재 AIDC/MESS 실제 P/Q를 OpenDSS에 반영
2. 현재 Tap 상태와 Pending Control Queue를 유지
3. Native OpenDSS AC Solve
4. 실제 감지 전압을 기준으로 자동 RegControl 판단
5. Delay 및 TapDelay에 따라 예약된 Tap Action 실행
6. 필요한 추가 AC Solve 수행
7. 제어 안정 상태 및 미처리 Queue 확인
8. 현재 노드·상 전압, 선로·변압기 정격, Tap 상태 기록
9. 다음 15분 구간으로 상태를 연속적으로 전달

단순히 슬롯마다 `SolveSnap()` 1회만 호출하고 Tap이 자동으로 반응했다고 판단하지 마라.

**Native TIME Control Queue를 시간에 따라 실제로 처리해야 한다.**

기존 V42의 `CommonClock.settle_slot()`을 재사용한다.

STATIC Control Iteration 횟수를 실제 물리적 경과시간으로 간주하지 않는다.

같은 Actual 날짜의 슬롯 사이에서는 Tap 및 Queue 상태를 유지한다.

다른 날짜의 독립 Case나 Planning Context의 Tap 상태를 섞지 않는다.

### Prefix 시간축 연결

현재 V44의 Planning Issue는 D-1 18:00이며, Actual 평가 구간은 D-day 96슬롯이다.

V43의 24슬롯 Prefix와 V42 SVR11의 96슬롯 TIME Driver 간 차이를 명시적으로 검사하라.

Prefix 상태를 사용해야 한다면 시간축 Adapter에서 정확히 연결하고, D-day 00:00에 Tap이나 Queue를 임의로 초기화하지 마라.

반대로 독립 Source Initial State에서 D-day 평가를 시작하는 계약이라면 그 이유와 초기 상태 근거를 명확히 기록하라.

**24슬롯 Prefix와 96슬롯 평가 사이의 Tap History가 실제로 일치하는지 검증하지 않은 상태로 PASS 처리하지 마라.**

## 5. V44의 모든 Arm·Stage에 동일한 SVR11 계통 적용

SVR11은 Actual에만 설치하는 장비가 아니다.

**Planning과 Actual 모두에서 동일한 11뱅크가 존재해야 한다.**

### B0

- 기존 R0/FCFS 유지
- Planning Reference가 SVR11 계통을 사용
- Actual FCFS 부하로 SVR11 AUTO/TIME 동작
- Fresh96 전체 AC 검증

### B1

- PR189 Fast A1 유지
- 새 SVR11 Forecast 민감도 생성
- Known 동결 계획 + 연구용 허용창 완화
- Unknown R1-FLEX30-C1
- Unknown Current AC도 SVR11 계통에서 평가
- Actual/Fresh에서 40개 제어기 자동 동작

### B2

- 같은 날짜 B0 Planning Reference 고정
- 기존 K16/K32/K48
- 기존 Adaptive Beam + 4-MESS Direct Joint MILP
- 새 SVR11 계통 계수 사용
- 기존 MESS 정수·P/Q/SOC/PCS/이동 제약 유지
- Actual FCFS 부하와 동결 MESS P/Q에 SVR11 자동 동작

### B3

- 동일 날짜 B1 A1 재사용
- M1 → A2 → M2
- A2에서도 동일한 SVR11 계통 및 새 전기계수 적용
- 최종 AIDC/MESS 동결
- Actual에서 독립적인 40-RegControl 자동 운전

B1과 B3의 Unknown 민감도 및 Current AC 경로에도 새 계통을 적용한다.

원래 7-RegControl에서 생성된 Current AC 인증서·Cache·Affine 보정 증거를 SVR11 새 Case에 그대로 적용하지 마라.

새 Hardware/Scenario/Case SHA에 따라 필요한 검증과 Cache를 재생성한다.

## 6. 이전 최적화 결과와 새로운 물리 모델을 혼용하지 마라

현재 V43 B2는 원본 RegControl 7개로 Actual/Fresh를 수행했고 30개 슬롯에서 전압 위반이 발생했다.

그 결과는 원본 증거로 그대로 보존한다.

SVR11이 추가됐다고 이전 B2 계획을 새 SVR11 환경에서 최적화한 결과처럼 취급하지 마라.

### 새로운 V44 전력망에서 필요한 작업

- 새 토폴로지 SHA
- 새 Equipment/Scenario SHA
- 새 전기계수 SHA
- 새 선로·변압기 행 축
- 새 Original FULL 물리 모델 검증
- 새 K16/K48 원본 모델 포함관계 검증
- 새 Current AC Source 인증
- 새 Fresh96 물리 검증

이전 Golden003 A1 및 V43 B2 FULL 가능해는 기존 7-RegControl 계통에 대한 결과다.

새로운 SVR11 환경에서는 이를 최종 인증된 Planning 결과로 재사용하지 않는다.

**알고리즘은 동일하게 유지하고, 변경된 물리 계통에 대해 새로 최적화·검증하도록 준비한다.**

May01~07의 입력과 모델을 따로 구성하되, 같은 날짜의 SVR11 Forecast 계수가 정확한 SHA로 일치한다면 B1/B2/B3가 공유할 수 있다.

서로 다른 날짜의 최적해나 모델 계수는 공유하지 않는다.

## 7. 기존 SVR11 성능 개선 및 검증 코드 재사용

새 구현으로 계산 시간을 다시 증가시키지 마라.

다음 기존 최적화를 조사하고 적용하라.

- Forecast Native Load Allocation Cache
- 동일한 Immutable Setter Schedule 재사용
- 날짜별 공통 Forecast 전기계수 생성
- Source/Hardware/Day/Slot SHA 기반 Cache
- 중단된 Slot의 정확한 Checkpoint Resume
- 독립 Probe의 완료 후 DSS Context 메모리 정리
- 기존 Native TIME Prefix 계산
- 기존 LDC Interval 보정
- 기존 Original FULL AC 검증
- 기존 Thermal/RegControl Inventory 감사

실제 엔진 상태, Tap, Control Queue, 과거 Solve 상태를 다른 독립 Probe 또는 Planning→Actual 사이에서 Cache하지 마라.

기존 SVR11 Epoch12의 검증·성능 개선 기능을 사용하고, 구버전 수학모델로 되돌리지 마라.

V44의 현재 Sparse/Compact/Beam/Joint 및 Actual Cache 개선도 유지한다.

기존 900초 Joint + 300초 K48 독립 Native 예산은 그대로 유지한다.

SVR11 이식 때문에 A1/A2/ M1/M2의 기존 최적화 수학이나 Budget 정책을 변경하지 마라.

## 8. 실제 시뮬레이션 상태 검증

코드 연결만 하고 SVR11 동작을 인증했다고 주장하지 마라.

실제 OpenDSS에서 최소 범위의 단일 시각 및 짧은 TIME Prefix 검증을 수행하라. V44 전체 7일 캠페인이나 전체 Native 최적화는 아직 시작하지 않는다.

최소 확인할 사항:

1. 원본 RegControl 7개 존재
2. 추가 RegControl 33개 존재
3. 전체 40개 활성화
4. 원래 Capacitor 4개 Fixed ON
5. 추가 CapControl/DSTATCOM 없음
6. BUS82의 Epoch12 최종 연결 일치
7. 신규 직렬 변압기·상별 Rating 유효
8. Original Line Impedance/NormalAmps 유지
9. Voltage·Current·kVA 검사 유효
10. Native Tap Change 실제 발생 가능
11. Delay30·TapDelay2 및 Original7 설정 유지
12. TIME Queue가 실제 물리시각에 따라 처리됨
13. 동일 Actual 시뮬레이션의 이전 Tap 상태 유지
14. Planning→Actual Tap·Queue 전달 0회
15. Actual→Planning 미래 상태 읽기 0회
16. 슬롯별 P/Q Setter 및 MESS 부호·위치 매핑 정상
17. 새 Source/Hardware 계수와 실제 AC 축 일치

추가로, 실제 전압 위반이 있는 시각에서는 전압 최저·최고 Node/Phase, 해당 위치의 SVR 감지전압, Tap 단계, Control Queue, 실제 AIDC/MESS P/Q를 추출하라.

**단지 RegControl 40개가 있다는 사실만으로 전압 위반 0을 주장하지 마라.**

SVR11에서도 전압 위반이 남으면 기존 설비 상태와 원인을 기록하고, 장비 배치나 정격을 임의 수정하지 않는다.

기존 V43 B2 전압 위반 30슬롯이 SVR11로 해결되는지는 새 환경에서 Fresh96을 실제 수행하기 전까지 `NOT_TESTED`로 표시한다.

## 9. V44 캠페인 실행 준비는 그대로 유지

현재 V44는 May01~07 준비 단계다.

Main 레인:

- B0 → B1 → B3
- Worker 1개

B2 독립 레인:

- May01~07
- Worker 2개

이 구조는 변경하지 않는다.

실제 May01~07 캠페인 Worker를 시작하지 마라.

현재 `V44_PRESTART_BLOCKED` 상태를 유지하고, 다음 사항까지 확인한 후에만 별도 승인으로 실행 가능 상태를 판단한다.

- May02~07 초기 Running 사이트
- 날짜별 MESS 초기 위치·SOC
- SVR11 새 계통의 날짜별 Source
- 새 전기계수
- Original FULL 및 K48 수학·물리 모델 정합성
- Planning/Actual 독립 상태
- Unknown Current AC 인증
- Fresh96 안전성 검증 경로
- 기존 Binary Checkpoint Resume

과거 May2025 데이터로 장비 배치를 개발한 연구이므로 독립 Holdout 검증이라고 주장하지 마라.

기존 V43/V44 Raw·결과·B2 물리 FAIL 기록은 불변으로 보존한다.

## 10. 변경 Source Freeze 및 최종 보고

이번 SVR11 이식은 이전 V44의 7-RegControl 물리 모델에 대한 **명시적인 변경**이다.

따라서 변경된 물리모델을 동일 Source라고 속이지 말고, 새로운 V44 SVR11 Equipment Revision 및 Scientific Source Freeze를 만든다.

반면 기존 최적화 알고리즘의 Source 동등성은 별도로 인증한다.
