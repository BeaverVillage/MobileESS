# Default source Actual workload authority

The default source backend executes the original `v42_pr134_b1.replay.actual` fixed replay through the original native operations API. Its authoritative workload policy is `V39E_FROZEN_DA_FIXED_REPLAY`: accepted Planning power and service trajectories remain fixed, with no retrospective rescheduling. It does not introduce another job or unknown-arrival algorithm. The frozen source unknown-arrival policy is preserved in the input descriptor and Planning freeze; it does not make arbitrary caller workload state a source observation.

Before executing Actual, callers obtain `SourceOperationsBridge.expected_aidc_state(frozen)`. The resulting deterministic descriptor contains `source_semantics`, `aidc_decision_sha`, `aidc_schedule`, `known_job_actions`, and `unknown_arrival_policy`, all derived from the verified immutable freeze. The default SOURCE path requires the caller's `realized_inputs.aidc_state` to equal this descriptor before materialization. SOURCE load and PV arrays must also equal the original source daily parquet columns. Fake source fixtures remain control-flow evidence only.

After original source materialization, reconstructed physical `aidc_state` binds that verified descriptor to the existing `ACTUAL_FIXED_REPLAY_RECEIPT.json` content and source file record/SHA. The original receipt must exist, declare the exact original workload semantics and policy, and contain zero reoptimization and repair flags. Fresh uses the original frozen PCC/MESS arrays and source Actual exogenous producer. Arbitrary unused caller workload state cannot become physical workload authority. A custom feeder backend may reconstruct a different approved physical representation through the original ActualBackend interface and its own verified grid authority.

The native Planning freeze also seals raw bytes, sizes and SHA256 values for the two source Planning NPZ files and the source `V42_DAYAHEAD_DECISION_FREEZE.json`. The outer B3 freeze carries the same receipts. Reloading Planning, starting Actual and entering default Fresh independently rehash these exact confined files. Completed SOURCE Actual validation rehashes the cited `ACTUAL_FIXED_REPLAY_RECEIPT.json`, `FRESH_RESULT.json`, `RAW_CONTROL_LOG.json` and `RAW_PHYSICAL_INPUT_LOG.json` at their expected output paths; changing a raw artifact cannot preserve a saved PASS merely by leaving the saved result dictionaries intact.

No Actual, Native, source model, OpenDSS or large-data execution was performed to prepare this binding. The small tests compare the pure deterministic descriptor and receipt validation, including rejection of caller drift, unauthorized repair and policy changes.
