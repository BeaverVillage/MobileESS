============================================================
1. SCIENTIFIC GOAL
============================================================

Develop ONE job-specific TOTAL runtime prediction package suitable for the
V42 research experiment.

For job j:

    T_j = actual execution runtime

Primary outputs:

    Q50(T_j | x_j)
    Q90(T_j | x_j)

The model must distinguish short and long jobs.

Do NOT return to the vNext6 featureless behavior where all jobs receive nearly
the same Q90.

The primary problem to solve is:

    good overall calibration
    +
    sharp reservation
    +
    long-job protection

simultaneously.

6. FEATURE ENGINEERING
============================================================

Engineer physically meaningful workload descriptors.

At minimum evaluate:

    log_walltime = log1p(requested_seconds)

    log_gpu = log1p(num_gpus_req)

    log_nodes = log1p(num_nodes_req)

    log_cores = log1p(num_cores_req)

    log_memory = log1p(requested_memory_mib)

    gpu_per_node = GPU / nodes

    cores_per_node = cores / nodes

    cores_per_gpu = cores / GPU

    memory_per_gpu = memory / GPU

    memory_per_node = memory / nodes

    requested_gpu_time =
        requested_GPU * requested_seconds

    log_requested_gpu_time =
        log1p(requested_GPU * requested_seconds)

Handle zero/missing denominators explicitly.

Do not impute impossible physical values silently.

Keep missingness indicators where appropriate.

9. PRIMARY MODEL FAMILY
============================================================

Keep the first search compact and interpretable.

Use LightGBM Quantile as primary family unless reproduction shows a technical
reason not to.

Compare:

M1 — RAW-RUNTIME QUANTILE
    LightGBM quantile directly on runtime_seconds
    Q50 + Q90

M2 — LOG-RUNTIME QUANTILE
    target:
        y = log1p(runtime_seconds)

    Train Q50/Q90 in log space.

    Back-transform:
        runtime = expm1(y_hat)

M3 — WALLTIME-RELATIVE QUANTILE
    only as RESEARCH TRACE model

    Example target:
        y = log(runtime / requested_walltime)

    or another mathematically justified normalized target.

    Then reconstruct predicted runtime using requested walltime.

    This model MUST NOT interpret walltime as actual runtime.

M4 — LONG-TAIL MIXTURE / TWO-STAGE MODEL

    Stage 1:
        predict probability that runtime > 4 h

    Stage 2:
        separate or conditioned quantile regressors for short/medium/long
        runtime regimes

    The final Q50/Q90 must remain deterministic and callable for a new job.

M5 — SMALL ENSEMBLE
    only if M1–M4 show complementary error patterns on DEV/CAL.

Do NOT add TFT, DeepAR, Transformer, neural survival, or large neural models
in this task unless all compact models fail for a clearly diagnosed reason.

============================================================
12. MODEL SELECTION METRICS
============================================================

Do NOT select using one metric.

Primary Q90 requirements:

A. calibration:
    overall Q90 coverage should be close to nominal 90%.

Use a preregistered tolerance band such as:

    0.88 <= coverage <= 0.92

unless existing frozen project authority specifies a different band.

B. sharpness:
    Q90 pinball loss must not materially degrade relative to B0.

C. reservation efficiency:
    predicted reserved GPUh / actual GPUh must be substantially below W0.

D. long-job safety:
    >4 h coverage must not collapse as in vNext6.

E. GPU-weighted underprediction:
    must be explicitly reported.

F. stability:
    results should be consistent between DEV and CAL.

Do NOT obtain nominal coverage simply by multiplying all predictions by an
arbitrary factor.

Report:

Do not accept a model that reaches Q90 coverage by returning walltime-scale
durations.

Target is not an arbitrary fixed ratio alone.

Selection must use calibration + sharpness + queue utility jointly.
