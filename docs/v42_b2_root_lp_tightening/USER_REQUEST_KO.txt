## 1. 목표

현재 K48 Joint Critical-Grid MILP는 다음 결과를 얻었다.

- 인증 Global LB = 0.46498486997548166
- 검증 U4 UB = 0.6760534504652341
- Global Gap = 31.22069421%
- Root 완료시간 = 119.18초
- 마지막 Root IntInf = 1,152
- 입력 Binary = 9,322

이제 제약 수를 맹목적으로 늘리지 않고, 실제 Root LP의 분수해에서 위반되는 원본 유효 제약을 찾아 강화한다.

**원본 정수 가능영역은 유지하고 LP Relaxation만 축소하는 것을 목표로 한다.**

B. SOC–Charge/Discharge Mode–Travel 결합 유효 부등식

각 후보의 효과를 분리해 측정한 뒤에만 결합 가능성을 검토한다.

## 3. Root LP 분수해 확보

PR211의 K48 행렬·Domain·실행 SHA를 그대로 재사용한다.

가능하면 저장된 Native Root Primal을 독립 검증한다.

실제 분수 Root 벡터가 저장되지 않았다면 K48의 Binary만 Relax한 전용 Root LP 모델을 별도로 구성하라.

- 동일 원본 Rows
- 동일 RHS/Sense
- 동일 Bounds
- 동일 rho Objective
- Binary만 C로 완화
- 추가 물리 완화 없음

LP가 실제 OPTIMAL로 종료하고 원본 좌표계의 Primal/Dual/Bounds/행 잔차가 검증된 경우에만 Separation에 사용한다.

중단된 Barrier의 로그상 목적값이나 IntInf 수치만으로 LP 해를 만들어내지 마라.

Root LP 해에서 다음을 분석한다.

- Fractional node_activity
- Fractional charge_mode
- Fractional route_flow
- Pch/Pdis simultaneous activity
- SOC와 Energy Balance
- Travel Arc 및 transit 상태
- Critical line/time/phase별 P/Q 기여
- Root 목적값 및 유효한 LP 하한

Fractional 수와 Root Gap을 별도 기록한다.

## 4. 후보 A — Fractional Root Grid Separation

기존 CG는 Joint의 정수해에서 위반 제약을 선정했다.

이번에는 검증된 Fractional Root Point에 대해 누락된 원본 Security 행 전체를 검사한다.

- line_thermal_face
- transformer_kVA
- NormalAmps
- voltage_upper
- voltage_lower

원본 FULL의 response/injection/correction 정의를 정확히 복원한다.

저장 원본 계수와 RHS를 Exact Fraction으로 검증한다.

위반된 계통 제약 중 16개 이하만 선택한다.

원본과 독립 검증을 통과한 행만 추가한다.

모든 새 행은 원본 FULL 가능영역의 모든 정수해에서 유효해야 한다.

보수적 Binary64 Outward Transport를 유지한다.

추가 행 선택은 실제 Fractional Root 위반량과 계통 민감도를 기반으로 한다.

## 5. 후보 B — SOC–Mode–Travel 강화 제약

차량 m, 슬롯 t에서 다음을 정의한다.

C_mt = Σ_s Pch[m,s,t]

D_mt = Σ_s Pdis[m,s,t]

T_mt = Σ_{a: depart(a)=t} travel_energy[a] × route_flow[m,a]

현재 원본 SOC 제약은

E[m,t+1] = E[m,t]
          + η_charge × Δt × C_mt
          - Δt / η_discharge × D_mt
          - T_mt

이다.

다음 두 유효 부등식을 후보로 구성한다.

### 후보 B1: 방전·이동 에너지 가용성

E[m,t] >= E_min
           + Δt/η_discharge × D_mt
           + T_mt

### 후보 B2: 충전 저장공간 가용성

E[m,t] <= E_max
           - η_charge × Δt × C_mt

총 후보는 2 × 4 × 96 = 768행이다.

단, 모델에 바로 모두 삽입하지 마라.

먼저 원본 Binary Route·Mode·연결 제약에서 이 부등식들이 모든 실제 정수 운전에 유효함을 독립적으로 증명하라.

특히 다음을 확인한다.

- 이동 출발 슬롯의 Travel Energy Debit
- 이동 중 충방전 금지
- Charge/Discharge Mode 배타성
- 하나의 차량이 하나의 위치에만 접속한다는 조건
- 원본 SOC Bounds 및 terminal 조건
- 효율·시간계수의 정확한 원본 binary64 값

원본에서 정의되지 않은 새로운 물리조건을 가정하면 안 된다.

저장 Compact/C3A의 SOC alias와 route_flow 축을 실제 원본으로 역매핑한다.

원본 integer feasible point 전체를 보존한다는 exact proof를 작성한다.

이후 Root fractional point에서 실제 위반하는 행만 선택한다.

최대 32개 후보를 초기 강화 대상으로 한다.

실제로 위반하지 않거나 기존 LP에서 이미 함의되는 행은 삽입하지 않는다.

새 Binary를 추가하지 않는다.

## 7. Native 실행 정책

현재 B1 캠페인이 진행 중이므로 B1이 우선이다.

**B1 Heavy Solver가 실행 중일 때 B2 Heavy Native를 실행하지 마라.**

지금은 Native0 기반 코드 작성·exact proof·기존 증거 감사부터 진행한다.

B1의 실제 실행 종료 또는 안전한 독립 실행 자원 허가를 확인한 경우에만 다음 제한을 적용한다.

- Worker=1
- Threads=1
- Base LP 1회 최대 240초
- GRID LP 1회 최대 240초
- SOC LP 1회 최대 240초
- 총 3회 이하
- 전체 신규 요청 Native 최대 720초
- Full MILP Branch-and-Bound 실행 0회
- 5월 공식 캠페인 실행 0회
- IEEE8500 실행 0회

첫 Base LP를 유효하게 확보하지 못하면 나머지 Native 실행을 중단하라.

두 후보의 Native0 유효성 또는 실제 분수해 위반 증거가 없으면 해당 후보 실행을 생략하라.

모델 확대와 메모리 한계를 사전 측정하고 기존 RAM/Commit Safety Gate를 유지한다.
