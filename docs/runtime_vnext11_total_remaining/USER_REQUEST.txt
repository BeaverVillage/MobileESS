============================================================
0. WHY V11 EXISTS
============================================================

Runtime-vNext10 established several important negative findings.

1. Simply refining hazard tail resolution did NOT solve long-runtime safety.

2. Static probability calibration could severely damage temporal
   generalization.

Example:
    raw T1 fold4 Q90 coverage ~88.33%
    selected calibrated fold4 coverage = 39.56%

3. Pre-April selected V10:
    pooled Q90 coverage = 88.81%
    min-fold coverage = 39.56%
    >4h coverage = 69.65%

4. April exposed:
    total Q90 coverage = 68.18%
    >4h coverage = 64.03%
    >24h coverage = 13.40%

5. The SAME total-runtime distribution produced:
    April total coverage = 68.18%
    April conditional remaining coverage = 94.12%

6. Tail-grid refinement improved mathematical support but did not solve
   predictive tail safety.

7. V10 successfully fixed:
    monotonicity,
    zero-support,
    finite proper distribution score.

Do NOT discard these successful numerical fixes.

But do NOT continue the assumption that one hazard distribution must solve
both pre-start TOTAL runtime and in-execution REMAINING runtime.

============================================================
43. MOST IMPORTANT SCIENTIFIC CHANGE
============================================================

V6–V10 tried progressively stronger versions of:

    one TOTAL-runtime representation
        ->
    use it both before and during execution.

V11 explicitly recognizes that the available information changes after a job
starts.

BEFORE START:

    request descriptors
        ->
    TOTAL runtime Q50/Q90

AFTER START:

    request descriptors
    + causally observed elapsed execution
        ->
    REMAINING runtime Q50/Q90

These are related prediction problems, but not identical information states.

Do not force one model to solve both merely for implementation simplicity.
