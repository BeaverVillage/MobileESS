3. DEFINE FOUR PRIMARY TARGET ARMS
============================================================

Build and preserve the following target definitions.

------------------------------------------------------------
T0 — CURRENT_SUBMIT_LIFETIME_GPUH_HOURLY
------------------------------------------------------------

Exact existing CC4 target.

24 values/day.

For each D-day hour h:

sum:
requested_GPU *
realized total runtime hours

for eligible jobs submitted in that D-day hour.

This is the exact baseline.

------------------------------------------------------------
T1 — SUBMIT_REQUESTED_GPU_HOURLY
------------------------------------------------------------

Use the SAME submit-hour population as T0.

For each hour:

sum requested_GPU

of jobs submitted in that hour.

Purpose:

isolate whether multiplying by full realized runtime is the major source of
burstiness / unpredictability.

Do NOT claim T1 is the final operational target.

It is a diagnostic target.

------------------------------------------------------------
T2 — UNKNOWN_ACTIVE_GPU_OCCUPANCY_HOURLY
------------------------------------------------------------

This target is based on actual execution overlap, not submit-hour lifetime mass.

Unknown-job population:

jobs with:

submit_time > D-1 18:00 issue

that have actual execution overlap with day D.

Exclude jobs already submitted by issue:
those are D-1 KNOWN jobs and belong to the known-job optimizer population.

For each D-day hour h:

GPUh_unknown(h)
=
sum over future-submitted jobs j of

requested_GPU_j
*
overlap_hours(
    [actual_start_j, actual_end_j),
    hour_h
)

Training/evaluation labels may use historical realized start/end.

Those fields are LABEL-ONLY.

They must never enter forecast features at their historical issue.

Also store:

average_active_GPU(h) = GPUh_unknown(h) / 1 h

which is numerically equal but semantically useful.

------------------------------------------------------------
T3 — UNKNOWN_ACTIVE_GPU_OCCUPANCY_15MIN
------------------------------------------------------------

Same unknown-job population as T2.

Use the native 15-minute electrical resolution.

96 values/day.

For each 15-min slot t:

GPUh_unknown(t)
=
sum_j requested_GPU_j
*
overlap_hours(
    [actual_start_j, actual_end_j),
    slot_t
)

Also store:

average_active_GPU(t)
=
GPUh_unknown(t) / 0.25 h

Use average_active_GPU as the primary T3 prediction target,
because active GPU occupancy maps naturally to instantaneous IT/PCC power.

Preserve GPUh-per-slot for exact daily mass conservation.

Verify:

sum_t GPUh_unknown(t)

exactly equals day-D future-submitted execution-overlap GPUh
within numerical tolerance.

34. MOST IMPORTANT SCIENTIFIC GOAL
============================================================

We are trying to determine whether the previous CC4 difficulty came mainly
from:

A. model architecture,

B. poor feature-to-target temporal mapping,

C. an operationally misaligned target,

D. genuine irreducible burst/distribution-shift uncertainty.

The experiment must separate these explanations rather than simply search
for a better score.
