## 3. Known Job과 Unknown Job을 명확히 분리

V43의 핵심 구조는 다음과 같다.

### Known Job

D-1 18:00에 이미 알려진 작업을 Planning에서 최적화한다.

- 승인된 Start/Finish Domain
- 데이터센터 위치
- Timeshift/Migration 권한
- GPU/Rack 및 WAN
- 기존 QoS/Deadline
- AIDC P/Q와 전력망 제약

Planning 종료 후 Known Job 실행 명령은 동결한다.

Actual에서는 계획된 작업을 시간순으로 수행하고 현재 물리 자원과 안전 조건을 재검증한다.

불법적인 명령은 실행하지 않고 명시적인 Queue 또는 기존 허용된 Corrective 경로로 처리한다.

### Unknown Job

D-1 18:00 이후 개별 UID가 아직 알려지지 않은 작업이다.

Day-Ahead에서는 CC4 예측과 기존 익명 Workload Envelope만 사용한다.

미래 Unknown UID, 실제 Submit Time, 실제 Runtime, 미래 데이터센터 선택 및 Actual 종료정보를 Planning에서 읽지 않는다.

Unknown Job이 실제 도착하면:

1. Submit 관측
2. 공개 메타데이터 및 Runtime Q50 확인
3. 기존 Reference 규칙으로 기본 사이트 배정
4. 아직 PENDING이고 실행 전이라면 Pre-site 후보 평가
5. 실행 가능한 더 좋은 사이트가 있으면 선택
6. 없으면 원래 사이트 또는 Queue
7. 실행 후 실제 Runtime·완료·Carryout을 기록

**Unknown Pre-site는 이미 RUNNING 중인 작업의 Migration이 아니다.**

Running Migration은 별도 기존 정책으로 유지하고 이번 첫 통합에서는 새로운 권한을 부여하지 않는다.

- PR226: E1/FLEX30 Preplacement 연구
- PR228: Known 동결·Unknown 후보 Fallback

### 4.1 초기 사이트와 Pre-site 분리

Unknown Job 최초 배치는 기존의 Causal Reference/Compatible Site 규칙을 사용한다.

최초 배치 단계에서는 전력망 민감도로 기본 사이트를 변경하지 않는다.

그 후 Pre-site 단계에서만 다음 대체 후보를 평가한다.

- 다른 Source-compatible AIDC
- GPU 및 Rack 수용 가능
- 요청된 Gang 전체 수용
- 데이터 접근 또는 전송 준비 가능
- Source QoS/Deadline 만족
- 기존 확정 예약과 충돌하지 않음
- 실제 전력망 제약 충족

기본 배치 권한과 Pre-site 변경 권한은 동일하다고 가정하지 않는다.

### 4.2 최대 선로 부하율 기반 의사결정

Unknown Job \(j\)의 배치 후보 \(s\)에 대해 다음 목적을 사용한다.

\[
s_j^* =
\underset{s\in\mathcal S_j^{feasible}}{\arg\min}
\max_{\tau,\ell,\phi}
\widehat{\rho}_{\ell,\phi,\tau}(s)
\]

여기서 평가 대상은 다음과 같다.

- IEEE123 원본 모든 선로
- 각 선로의 모든 상
- 현재 시각부터 남은 평가 구간
- 해당 Job의 Q50 예상 서비스 구간
- 기존 Known Job 동결 명령
- 이전에 확정한 Unknown 예약
- 기존 MESS P/Q 및 위치
- 현재 시각까지 관측된 실제 GPU/전력망 상태

한 선로나 한 슬롯의 감도만 이용하지 않는다.

민감도는 Signed Electrical Sensitivity와 원본 C1 Affine P/Q 관계를 사용한다.

후보 계산에서 발생하는 전압·전류·변압기 및 GPU/Rack 위반은 목적함수의 가중 페널티가 아니라 Hard Reject로 처리한다.

### 4.3 후보 순위

후보 선택 우선순위:

1. 실제 실행 권한과 물리적 실행가능성
2. 예상 최대 선로·상 부하율 최소
3. Critical Loading Hours 감소
4. Q90 Runtime/Rebound 위험 감소
5. 추가 Delay/Transfer/Interruption 최소
6. 결정적 Site/Start Tie-break

동일한 실행 조건에서 기존 기본 사이트보다 유의미하게 개선되는 경우에만 Pre-site를 선택한다.

실행 가능한 대체 사이트가 없는 경우 기본 사이트를 유지한다.

기본 사이트도 불가능하면 Queue로 남긴다.

### 4.4 Actual의 계산 제한

Actual에서 원본 AIDC 또는 MESS의 Global MILP를 다시 풀지 않는다.

후보 생성·민감도 점수 계산·Current Hard Guard 및 필요한 AC 확인만 수행한다.

15분 제어 슬롯보다 계산시간이 길어지지 않도록 캐시와 후보 재사용을 도입한다.

실제 P50/P95/Max Controller Wall Time을 계측한다.

미래 AC Tap 동작, 실제 미래 Weather, 실제 미래 Runtime/Completion을 미리 알고 있다고 가정하지 않는다.

Current AC Hard Admission과 미래 Q50 기반 예측 점수를 명확히 구분한다.

## 5. Pre-site 실행 권한 및 WAN 계약

이 부분은 반드시 실제 연구 결과의 해석까지 고려하라.

기존 PR224/226/228에서는 Source 권한이 없거나 GPU/Q90 제약에서 거부되어 Pre-site가 실행되지 않는 경우가 있었다.

따라서 다음 계약을 분리한다.

### Strict Source Mode

- 실제 Source에서 확인된 Pre-site 권한만 사용
- 금지된 목적지 제외
- 데이터 접근 가능성이 확인된 후보만 선택
- WAN 준비시간과 완료시각 적용
- QoS/Deadline 유지
- 권한이 없으면 Pre-site 실행하지 않음

### Research R1 Mode

공유 데이터 또는 사전 Stage된 입력을 가정하는 별도 연구용 시나리오다.

- Source의 명시적 금지사항은 그대로 유지
- 기존 E1/FLEX30 참여 규칙은 별도 연구 계약으로 표시
- 연구에서 추가한 데이터 접근 가정은 `ASSUMED`로 표시
- 고객의 실제 배치 허가 또는 측정 WAN 실적으로 주장하지 않음
- 원본 GPU/Rack/전력망 Hard 제약 유지
- 서비스량, Carryout, QoS 위험을 전부 기록

Research R2의 실제 데이터 전송 기반 Pre-site는 별도의 사용 승인과 Source/Timing 검증이 없다면 HOLD를 유지한다.

R1 연구 가정을 Strict Production PASS로 승격하지 않는다.

**민감도 점수가 좋다는 이유로 허가받지 않은 Job 이동을 실행하지 마라.**

## 6. Pre-site 효과를 독립적으로 검증

동일한 Day-Ahead 계획과 동일한 Actual 입력에 대해 다음을 비교한다.

### C0 — Basic Unknown Placement

- 원래 Reference Site 사용
- 민감도 기반 대체 사이트 탐색 없음
- 기존 물리적 Queue/Fallback 유지

### C1 — Sensitivity Pre-site

- 초기 Reference Site 동일
- 동일 실제 Job 도착
- 동일 Known Schedule
- 동일 MESS 계획
- 동일 GPU·QoS·WAN Hard Constraints
- PENDING 상태에서만 대체 사이트 평가
- 민감도 기반 최적 후보 선택

Strict C1과 연구 가정 R1을 섞지 말고 별도 Policy ID로 구분하라.

### 검증 지표

반드시 다음 수치를 보고한다.

- Unknown Submitted UID
- Unknown Basic Site Assigned
- Pre-site Eligible UID
- Pre-site Candidate Evaluated
- Pre-site Hard Feasible
- Pre-site Selected
- Pre-site Actually Started
- Pre-site Changed GPUh
- Unknown Queue
- Completion 및 Terminal Carryout
- 지연/서비스 위험
- GPU/Rack/WAN 위반 수
- Actual 최대 선로·상 부하율
- Actual 일평균/일최대 Loading
- Fresh AC 전압·열적 위반
- Controller P50/P95/Max Wall Time

`Selected`와 `Executed`를 반드시 구분한다.

Pre-site 후보가 있었으나 실제 실행되지 않은 원인도 UID 단위로 추적한다.

Strict Source Mode에서 변경 0건이 나오면 해당 결과를 그대로 보존하고 원인을 보고한다.

전력망 개선을 만들기 위해 Source 권한을 조작하지 않는다.

## 7. 최신 MESS 최적화 알고리즘 통합

다음 작업은 PR189 B1 복원과 Unknown Pre-site 독립 검증 이후 수행한다.

기존 구현을 우선 재사용한다.

- PR222: Incumbent 보존 및 Pool 누락 수정
- V42.2 PR231: Seedless K48와 Joint MILP 연결

### 7.1 MESS 물리 계약

- IEEE123
- 4대 MESS
- 원본 24개 연결 후보 노드
- 원본 교통 DAG 및 이동시간
- 실제 이동에너지
- Pch/Pdis/Q
- SOC 및 종단 SOC
- 384 Charge Mode
- PCS P/Q 제약

4대 각각 STAY와 다양한 MOVE 경로를 자유롭게 선택하게 한다.

STAY/MOVE를 강제하지 않는다.

네 대가 동시에 서로 다른 경로로 이동할 수 있어야 한다.

### 7.2 MESS 단계

먼저 PR189 AIDC/Reference로부터 V43 전용 MESS Case를 생성한다.

그다음 다음 과정을 수행한다.

1. Seedless K48 또는 검증된 유효 Global LB 계산
2. Beam Search로 다양한 경로 후보 생성
3. 4대 공동 Direct Joint MILP
4. P/Q/SOC/Charge Mode 최적화
5. Original FULL Replay
6. FULL-feasible UB 저장
7. Adaptive Beam 반복 및 Global Gap 평가

K48에서 계산한 LB와 Joint MILP의 UB는 정확한 동일 Case에 한해 결합한다.

PR220의 기존 UB `0.539831...`이나 기존 K48 LB를 새 V43 Case의 인증으로 이전하지 않는다.

제한된 Beam Pool의 `ObjBound`를 전체 원본 문제의 Global LB로 사용하지 않는다.

### 7.3 예산 및 성능

M-stage Native 예산은 기존 1,800초/Stage를 유지한다.

기존 K48 별도 한도 및 Joint 단일 호출 한도를 유지한다.

- Worker=1
- Threads=1
- Heavy Solve 동시 실행 금지
- Native/Build/Validation/Wall 분리 계측
- 불변 Static Cache는 정확한 Source/Case 일치 시만 재사용

M Stage의 FULL-feasible 결과와 Global Gap 인증을 별도로 기록한다.

3% Gap을 달성하지 못했다고 수치 조작이나 잘못된 LB 승격을 하지 않는다.

V43는 기존 비교군의 의미를 보존해야 한다.

|---|---|---|

B3의 단계는 다음과 같다.

`A1 → M1 → A2 → M2`

A2에서는 M1 MESS 결정 고정, M2에서는 A2 AIDC 결정 고정이라는 기존 교대 최적화 계약을 유지한다.

각 단계의 Original FULL 검증을 보존한다.

모든 B0/B1/B2/B3의 Actual에서 Unknown C0/C1 또는 해당 연구용 R1을 일관된 실험 정책으로 비교한다.

동일한 Day-Ahead 계획을 C0/C1 양쪽에서 사용하므로 **두 정책의 실제 전력망 차이는 Unknown Pre-site 제어 효과로 식별 가능하게** 구성하라.

단, Unknown 제어가 후속 작업 큐 및 Rebound에 미치는 영향은 각 Actual의 상태전이에 자연스럽게 반영한다.

- Unknown Pre-site 실행 횟수
- Current AC/Fresh AC 실패
- Source SHA 및 변경 이력

문제가 발생하면:

1. 원본 증거와 실제 오류 확인
2. 근본 원인 분류
3. 실행 중 Worker 안전 종료 및 원장 정산
4. Source 수정
5. Native0 및 회귀 테스트
6. 새 Commit/Source Freeze
7. 실패 비교군의 새 Attempt 생성
8. 해당 비교군의 처음부터 재실행

새 Attempt는 Native=0에서 시작하지만 이전 Attempt 원장은 보존한다.

실행 환경이나 Codex 세션이 중단되면 정확한 Resume Manifest와 상태를 남겨라.

대화가 무기한 유지된다고 가정하지 말고 감독 가능한 Worker와 재개 절차를 사용한다.

사용자가 명시적으로 중지하지 않는 한, 승인된 캠페인 범위에서 자동 복구를 계속한다.

## 15. 최종 지시

**V43는 PR189의 빠른 Day-Ahead AIDC 알고리즘을 기반으로 하되, Unknown Job에 대한 민감도 기반 Pre-site와 최신 MESS 알고리즘을 통합하는 연구 버전이다.**

**PR189 복원 → V43 Golden B1 PASS → Unknown C0/C1 Pre-site Actual 검증 → 4-MESS K48/Beam–Joint 연결 → B0/B1/B2/B3 May01 PASS → 5월 전체 캠페인**

현재 V42.2를 계속 최적화하려고 V43에도 그 대형 LP를 이식하지 마라.

기존 알고리즘과 검증된 소스들을 가능한 한 재사용하고, 새 기능이 PR189의 빠른 AIDC 최적화 성능을 훼손하지 않도록 분리하라.

모든 비교군에서 알고리즘의 실행가능성, 전역 최적성 인증, Actual 물리 안전성 및 연구용 권한 가정을 구분하라.

먼저 V43 브랜치와 Rollback 기반을 봉인하고, PR189 May01 Golden Baseline 재현을 시작하라. 이후 승인된 순서대로 실험과 통합을 계속한다.
