## 4. 최신 MESS 알고리즘 통합

**PR189의 오래된 초기 FULL MILP Seed 경로를 공식 M-stage로 사용하지 마라.**

최신 알고리즘은 다음 구조로 통합한다.

### Global LB

- Seedless K48
- 원본 MESS Full-domain과 유효한 완화 포함관계 검증
- Original Grid Critical Rows
- 독립 Global LB 인증
- K48 이전의 K16/K32 과정은 기존 유효 구현을 활용
- 불필요한 Full Root LP 반복 금지

기준 소스: PR210/211 및 V42.2 PR231의 Seedless K48 경로.

### Feasible UB

- Adaptive Beam Search
- 네 차량의 STAY·단일 MOVE·복수 MOVE 후보
- Multi-Critical Grid Loading
- SOC 및 Rebound 고려
- 4-MESS Direct Joint MILP
- P/Q/SOC/Charge Mode 공동 최적화
- Original FULL Replay

기준 소스: PR219/220/221/222 및 후속 V42.2 연결.

### 4대 MESS 원본 물리 모델

다음을 유지한다.

- 원본 네 차량과 24개 연결 후보 노드
- 각 차량의 독립 이동경로
- 교통 DAG 및 ETA
- 이동에너지
- Charge/Discharge/Reactive Power
- SOC 96슬롯 및 종단 조건
- 384 Charge Mode
- PCS16
- 원본 모든 선로·상, 전압, 변압기 제약
- 배터리 및 이동 중 접속 제약

**STAY/MOVE를 강제하지 않는다.**

네 차량 모두 서로 다른 경로로 동시에 이동할 수 있어야 한다.

단일 차량이나 특정 경로 주변만 반복해서 탐색하지 않는다.

Beam Pool은 후보 탐색을 위한 것이며 전체 이동경로 영역의 대체물이 아니다.

Direct Joint MILP의 제한된 ObjBound를 Global LB로 사용하지 않는다.

과거 PR220 UB=0.539831 및 K48 LB=0.464985는 다른 Case에 대한 연구 결과이므로 V43 공식 인증값으로 가져오지 않는다.

새 B2·B3 M1·B3 M2 Case에서 각각 유효한 UB/LB를 계산하라.

## 5. M-stage 준비 및 실제 실행

### 5.1 기존 파일 활용

기존 로컬 Source/Case/Static Cache를 찾아 활용한다.

- 기존 K48 수학적 정식화
- Beam Search
- Direct Joint MILP
- MESS FULL validator
- Source18r Compact/PCS 검증 코드
- 기존 B2/M1/M2 Adapter
- Static Cache 및 후보 점수 벡터화

전체 파일을 새로운 이름으로 중복 복사하거나 모든 모델을 처음부터 재구성하지 마라.

단, 현재 V43의 원본 계통·7 RegControl 및 PR189 AIDC 전력망 Case에 연결해야 한다.

기존 11SVR, D0 과학적 모델, 다른 C1 전기계수, 기존 Source18r 결과를 무검증으로 혼합하지 않는다.

### 5.2 모델 동치성 검사

실제 Gurobi 실행 전 다음을 Native0에서 검증하라.

- V43 원본 Source SHA
- 4-MESS 원본 Full/Compact 매핑
- 원본 목표함수
- 이동경로·Mode·SOC·P/Q 변수 의미
- Original Integer Domain
- B2/B3 고정 AIDC 입력
- B3 M1→A2→M2 연결
- Grid/PCC P/Q 계수
- K48의 원본 전체 공간에 대한 유효 하한 성질
- Joint MILP 후보 해의 Original FULL Lift

Native0 결과를 실제 최적화 완료로 주장하지 않는다.

### 5.3 실행 예산

M-stage당 기존 1,800초 Native 예산을 유지한다.

- Worker 1
- Gurobi Threads 1
- Heavy Solver 동시 실행 1개
- Native와 Build/Validation Wall 분리
- Stage별 독립 예산 및 실패 원장 유지
- M-stage 3% Global Gap 목표
- 이전 실행과 새 실행 예산을 잘못 합치지 않음

실제 문제에서 3% Gap을 얻지 못하더라도, Original FULL-feasible UB를 얻었다면 그 자체의 물리적 가능성과 Global Gap 미인증 상태를 분리해서 보고한다.

전체 비교를 위해 FULL-feasible MESS 계획을 사용한 Actual 진단은 수행할 수 있다. 다만 이를 `GLOBAL_GAP_PASS`라고 표시하지 않는다.

원본 FULL 해가 없으면 임의의 MESS 해를 만들어 사용하지 않는다.

## 6. May01 실행 순서

현재 진행 중인 Gate B C0/Strict C1 결과를 먼저 정산한다.

### Phase A — 기존 Actual Gate B 종료

- B1 Golden003 기준
- C0 Actual prefix + D-day 96
- Strict C1 Actual prefix + D-day 96
- 각각 독립 Fresh AC96
- GPU/Rack/WAN/Job 보존
- Known 계획 동결
- 미래 Unknown 정보 사용 금지
- 결과와 실행 원장 봉인

Strict Source에서 Pre-site 실행 0건이 발생하더라도 권한 부족이 정당하면 이를 결함이나 실험 실패로 조작하지 않는다.

기존 Actual에서 실제 결함이 발견되면 Source/Case/Raw 보존 후 독립 Attempt에서 수정한다.

### Phase B — B0 Baseline

PR189의 원본 B0 Reference를 불러온다.

- B1 최적화 명령을 혼입하지 않음
- MESS 최적화 P/Q 주입 없음
- 동일 기상·수요·PV·ML/CC4 Authority
- 원본 18:00 정보 기준
- 기존 Actual 이벤트 엔진 사용

B0의 Planning, Actual C0/C1, Fresh AC96을 독립 검증한다.

### Phase C — B2 MESS-only

B0 AIDC 계획을 고정한다.

- V43 B2 M Case 생성
- Seedless K48
- Beam Search
- 4대 Direct Joint MILP
- Original FULL Replay
- 최종 MESS 계획 Freeze
- C0/Strict C1 Actual96
- Fresh AC96

B0와 B2의 차이는 MESS 최적화 효과로 평가한다.

### Phase D — B3 Joint

- A1: PR189 기반 AIDC 최적화
- M1: A1 동결 후 MESS 최적화
- A2: M1 P/Q 및 물리 결정 고정 후 AIDC 최적화
- M2: A2 동결 후 최종 MESS 최적화

각 단계의 계획·인증·Source SHA를 따로 저장한다.

A2와 M2의 고정 입력을 이전 단계 결과와 정확하게 결합한다.

단계 간 UB/LB를 같은 문제의 인증처럼 혼합하지 않는다.

최종 A2/M2 동결 계획으로 C0/Strict C1 Actual96 및 Fresh AC96을 실행한다.

### 실행 실패 처리

B2가 실패했다고 원인과 무관한 B3까지 모두 중단하지 않는다.

공통 Source 또는 물리 Case가 손상된 경우에는 안전하게 HOLD한다.

개별 Arm/Stage의 실패는 증거를 보존하고 다른 독립 Arm의 실행 가능 여부를 판단한다.

한 비교군만 성공했다고 전체 May01 PASS를 선언하지 않는다.
