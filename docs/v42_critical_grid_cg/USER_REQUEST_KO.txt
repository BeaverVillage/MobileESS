# V42 — Critical-Grid Constraint Generation으로 Global LB 강화

Repository: BeaverVillage/MobileESS

## 0. 연구 목적과 기준

이번 작업은 기존 Source18r의 Full MILP를 다시 실행하지 않고, **4-MESS Joint Critical-Grid Reduced MILP에서 생략된 원본 계통 제약을 반복적으로 추가하여 Global Lower Bound를 강화하는 것**이다.

기준:

- Source18r / PR207: `497609b46faa14ea7e32a9483a333ab32fd264ef`
- 차량별 LB / PR209: `9383a99f1bdcabbd49c79b3ad9f9ee36d523868a`
- Joint16 / PR210: `6a8fd44f59f1f461c60d2d14f5f5be605e4ed640`
- 대상: IEEE123, B2, 2025-05-01
- 검증된 원본 FULL UB: `0.6760534504652341`
- Joint16 Global LB: `0.42547778318693985`
- Joint16 최종 정수해 목적값: `0.4258955562455018`
- 현재 Global Gap: `37.064475761%`
- 3% 목표 LB: `0.6557718469512771`

PR210의 360초 한도 실행은 실제 116.457초에 종료됐고, 축소 MIPGap은 0.098092843%다.

**같은 K16에 시간만 더 사용하는 것은 금지한다.**

이번에는 K16 정수해가 위반하는 원본 계통 제약을 찾아, 검증된 제약만 추가한다.

## 1. 최적화 구조

기존 Joint16의 전체 물리 영역과 이진변수 9,322개는 그대로 유지한다.

기존 제약 집합을 K16이라 하고, 매 반복에서 새 제약 집합 ΔK를 선택한다.

K_next = K_current ∪ ΔK

최적화 문제는 다음과 같다.

minimize rho_max

subject to:

- 모든 MESS의 96슬롯 물리 제약
- 원본 Route/SOC/P/Q/PCS16/Mode/이동에너지
- 각 k ∈ K_current에 대한 원본 계통 부등식
- rho_max의 원본 Bounds

**이전 계통 제약을 삭제하거나 하나의 가중합으로 대체하지 마라.**

모든 추가 제약은 원본 FULL에서 실제로 존재하는 제약이어야 한다.

원본 FULL 가능영역 F와 현재 축소 문제 J_K에 대해 반드시 다음을 보존한다.

F의 사영 ⊆ J_K

따라서

min(J_K) ≤ min(F)

이며, 유효하게 계산한 J_K의 Solver Lower Bound는 원본 문제의 Global LB 후보가 된다.

새 제약을 추가하면 축소 문제의 수학적 최적값은 감소하지 않는다. 단, TIME_LIMIT에서 얻은 개별 Solver Bound가 항상 단조 증가한다고 가정하지 마라.

## 3. 원본 전체 계통 제약을 이용한 Separation Oracle

가장 중요한 신규 구현이다.

PR210에서 확보한 Joint16의 최종 정수해를 원본 차량·시간·위치·P/Q 좌표로 복원한다.

그다음 원본 FULL의 누락된 계통 Security 제약을 검사한다.

검사 대상:

- `line_thermal_face`
- `transformer_kVA`
- `NormalAmps`
- `voltage_upper`
- `voltage_lower`

각 행의 실제 저장 RHS, Sense, 계수, 고정 AIDC, Forecast, Response Correction을 사용한다.

원본의 injection/response/helper 정의 등식은 현재 Joint 해에서 정확하게 재구성한다.

이때:

1. 원본 FULL의 차량 이동경로·정수 패턴을 변경하지 않는다.
2. 원본 Response 정의를 임의의 선형 근사로 교체하지 않는다.
3. 원래 저장된 binary64 계수를 수학적 Authority로 사용한다.
4. 기존 원본과 다른 AC/OpenDSS 계수를 가져오지 않는다.
5. Planning의 Forecast 계수와 Actual 계수를 섞지 않는다.

수치적 빠른 탐색에는 Sparse Matrix 연산을 사용하되, 실제 채택할 제약은 저장된 원본 계수와 Fraction 기반 독립 검산으로 확정한다.

Full-size Gurobi 모델을 생성할 필요는 없다.

원본 FULL CSR은 필요한 순간 읽기 전용으로 접근하며, 대형 행렬을 Solver 모델과 동시에 메모리에 중복 상주시켜 RAM 사용량을 급증시키지 마라.

## 4. 제약 위반량 계산

각 원본 행을 실제 부호와 Sense에 따라 표준화하고, Joint16 정수해에서 위반량을 계산한다.

예를 들어 thermal facet은

rho_max >= b_k + Σ_m a_km^T x_m

이므로

violation_k = b_k + Σ_m a_km^T x_m - rho_max

이다.

violation_k > 0이면 해당 원본 thermal 제약이 위반된다.

전압·변압기 등 다른 행은 원본 Sense에 맞춰 별도로 위반량을 계산한다.

행 종류마다 물리 단위가 다를 수 있으므로 원시 위반량과 정격·행 스케일 기준 정규화 위반량을 모두 저장한다.

원본 thermal facet의 부하율 위반량과 전압 pu 초과량을 같은 단위처럼 직접 비교하지 마라.

작은 수치 오차를 실제 물리 위반으로 오인하지 않도록 interval 또는 정확 산술을 활용해 판정한다.

**Separation Oracle의 목적은 원본 FULL에서 빠진 제약 중 현재 Joint 정수해를 실제로 배제하는 유효한 원본 부등식을 찾는 것이다.**

원본 등식으로부터 소거할 수 없는 행, 좌표가 모호한 행, 수치적 정당성이 불명확한 행은 자동 추가하지 말고 별도로 보고한다.

## 5. 새 계통 제약 선정 정책

초기 집합 K16을 고정한다.

첫 번째 반복에서는 누락된 원본 계통 Security 행 중 실제 위반이 있는 제약을 최대 16개 선정한다.

선정 시 다음을 고려한다.

- 원본 위반량과 정규화 위반량
- 기존 K16과의 중복성
- 서로 다른 선로·상·시간의 대표성
- 충전 Rebound와 관련된 후속 시간대
- 원본 목적함수 rho_max와 직접 결합되는 제약
- 고정 전압·전류 정격 위반처럼 해의 가능성을 제한하는 제약

같은 선로·시간의 거의 동일한 Facet만 무분별하게 선택하지 마라.

단, 실제로 다른 유효 제약이라면 임의의 다양성 기준 때문에 무조건 제외하지도 마라.

각 후보별로 다음을 저장한다.

- 원본 FULL Row ID
- Row Family
- Line/Transformer/Bus/Phase
- Slot
- Facet
- 실제 위반량
- 정규화 위반량
- 원본 계수·RHS SHA
- 기존 K16과의 중복 검사
- 선정 또는 제외 사유

초기에는 16개를 초과하여 추가하지 마라.

실제 위반이 16개보다 적으면 확인된 유효 위반 제약만 추가한다.

## 6. Native0 Exact Cut Validation

새로운 계통 제약이 원본 FULL의 모든 가능해에서 성립한다는 것을 증명한다.

원본에서 도출한 정확한 행을 Joint Compact 좌표로 변환한다.

원본 P/Q, Response, RHS, 고정항 및 rho_max 부호가 일치해야 한다.

Native binary64로 전환할 때는 PR210에서 사용한 보수적 외향 RHS 보정 원칙을 유지한다.

새 계수가 Gurobi에 전달되는 과정에서 유효 원본 가능해가 배제되지 않는지 독립 검산한다.

검증 항목:

- 원본 행과 새 행의 정확한 대응
- 변수 매핑과 단위 일치
- Fraction 기준 계수 소거
- 원본 고정항 및 RHS
- Sense 및 rho_max 부호
- 보수적 반올림
- 원본 FULL U4 해의 새 제약 만족
- 실제 Gurobi Readback
- 기존 K16·물리 행·Bounds·Objective 변경 없음

Adversarial Test로 Row ID, Phase, RHS 부호, 계수, Source SHA, 반올림 방향 변조를 각각 거부하는지 확인한다.

검증 실패 시 Native Optimize를 실행하지 않는다.

## 7. 1차 최적화 — K16 + 추가 최대 16개

최종 Native0와 RAM 게이트가 PASS한 경우에만 수행한다.

설정:

- 1 Worker
- Threads=1
- TimeLimit=180초
- MIPGap=0.03
- 기존 PR210 수치 허용오차 유지
- 기존 MIPFocus3·Seed42 유지
- Optimize 1회
- Full MILP/Full LP 실행 0회

기존 검증 U4 가능해를 새로운 축소 문제의 MIP Start로 전달한다.

PR210의 Joint16 정수해는 새로운 제약을 위반할 수 있으므로 MIP Start로 무조건 전달하지 마라. 새 제약까지 만족하는 경우에만 사용 가능하다.

Root/Node/ObjBound/ObjVal/MIPGap/Runtime/Memory를 모두 기록한다.

TIME_LIMIT라도 유효한 Global Solver Bound가 존재하면 독립 검증해 보존한다.

중단된 Solver Incumbent의 목적값을 Global LB로 사용하지 마라.

## 8. Global LB 계승 정책

기존 Joint16의 유효한 Global LB는 다음과 같다.

LB_old = 0.42547778318693985

새 문제는 기존 K16을 모두 유지하고 제약만 추가하므로, 유효성이 검증된 경우 LB_old는 계속 유효하다.

따라서 보고할 누적 하한은

LB_published = max(LB_old, LB_new_certified)

로 계산한다.

단, 원본 가능영역 포함관계가 깨지거나 새 모델의 Source/계수/Bounds/목적함수 무결성이 깨진 경우에는 새 결과뿐 아니라 그 모델에 대한 계승 주장도 거부한다.

Solver 수치 Bound의 독립 검산과 exact B&B trace 인증은 서로 구분하라.

Global Gap은 검증된 원본 FULL U4 UB만 사용한다.

GlobalGap = (0.6760534504652341 - LB_published) / 0.6760534504652341

목표는 Global Gap <= 3%다.

## 9. 2차 반복 — 개선이 있을 때만 실행

1차의 최종 인증을 마친 뒤 다음을 모두 만족할 경우에만 2차 반복을 허용한다.

- 신규 Certified Global LB 개선량 >= 0.005
- 1차에서 유효한 새로운 Joint 정수해 확보
- 새로운 정수해에서 기존에 포함하지 않은 원본 계통 위반 제약 확인
- 메모리·모델 규모 게이트 재통과
- 1차 종료 및 Native Ledger 완전성 확인

2차에서는 신규 Joint 정수해를 대상으로 Separation Oracle을 다시 실행한다.

추가 위반 제약은 최대 16개로 제한한다.

- 누적 추가 제약 최대 32개
- 최종 K 최대 48개
- 2차 Native TimeLimit=180초
- 2차 Optimize 최대 1회

기존 1차 제약과 K16은 모두 유지한다.

1차 후 유의미한 LB 개선이 없다면 2차는 실행하지 않는다.

1차에서 확인한 Solver TimeLimit, 실패 또는 예산 소진을 자동으로 초기화하여 같은 모델을 반복 실행하지 마라.

## 10. 전체 실행 제한

이번 연구 전체에서:

- 추가 Joint MILP Optimize 최대 2회
- 총 신규 Native 요청 예산 최대 360초
- 1 Worker × Threads1
- Full-size MILP Optimize 0회
- 별도 Full LP Optimize 0회
- Column Generation/DW/Benders 0회
- 가중치 최적화 0회
- 공식 캠페인 실행 0회
- 추가 날짜 실행 0회

모델 규모 안전 게이트:

- 입력 Binary = 9,322개 유지
- Columns는 기존 Joint16 기준을 유지
- Rows <= 160,000
- NNZ <= 1,800,000

수치가 이 게이트를 초과한다면 자동 확장하지 말고 실제 원인과 예상 RAM을 기록하고 중단한다.

RAM/Commit 정책은 PR210의 기존 검증된 admission 계약을 유지한다.

실행 전 다른 Heavy Gurobi Worker가 존재하면 대기하거나 실행을 중단하며, 기존 프로세스를 강제로 종료하지 않는다.

Available RAM, Commit Available, Process RSS, Private Commit, Gurobi MaxMemUsed를 구분해 보고한다.

## 11. 올바른 종료 판정

다음 상태 중 하나로 종료하라.

- `CG_GLOBAL_GAP_3PCT_PASS`
  - 유효한 누적 Global LB가 목표 이상이며 모든 독립 게이트 PASS

- `CG_LB_MATERIAL_IMPROVEMENT`
  - 3% 미달이지만 기존 Joint16 LB보다 최소 0.005 개선

- `CG_LB_NONMATERIAL`
  - 유효하나 LB 개선이 0.005 미만

- `CG_NO_VALID_VIOLATED_ROWS`
  - 검증 가능한 새 위반 제약을 확보하지 못함

- `CG_RESOURCE_OR_NUMERIC_STOP`
  - 메모리·수치·무결성 문제로 안전 중단

Separation Oracle에서 위반 제약을 발견하지 못했다는 것만으로 원본 FULL 최적성이 증명됐다고 주장하지 마라.

그 주장을 하려면 모든 생략 제약의 정확한 검사, 원본 FULL 사영의 유효성 및 축소 문제의 최적성 증명이 별도로 필요하다.

축소 Joint 정수해를 원본 FULL UB 또는 Actual OpenDSS PASS로 승격하지 마라.
