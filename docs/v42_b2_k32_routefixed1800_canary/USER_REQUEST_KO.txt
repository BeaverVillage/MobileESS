## 4. Stage B — 실제 MESS 이동경로 생성

이번 작업의 핵심 신규 모듈이다.

### 4.1 원본 Route DAG 재사용

원본 Source18r의 4-MESS·24개 접속 위치·96슬롯 DAG를 그대로 사용한다.

각 경로는 실제 저장된 다음 정보를 이용해야 한다.

- 출발 위치와 시간
- 도착 위치와 시간
- 원래 ETA
- 원래 이동에너지
- STAY / MOVE Arc
- 이동 이후 연결 가능 시간
- 원본 terminal slot96 의미

존재하지 않는 이동경로를 합성하지 않는다.

새로운 시간·거리·에너지 계수를 만들지 않는다.

출발 위치로 반드시 복귀해야 한다는 신규 제약도 추가하지 않는다.

### 4.2 Route Search

**Resource-Constrained Shortest Path Labeling + Bounded Beam Search**를 연구용 경로 후보 생성기로 사용한다.

시간확장 그래프의 Vertex:

`(MESS, Site, Slot)`

자원정보:

- 실제 도달시간
- 누적 이동에너지
- 연결 가능 시점
- 이후 충방전 기회
- SOC 가용성에 대한 안전한 필요조건

명백히 물리적으로 불가능하다고 증명할 수 있는 경로만 Hard Pruning한다.

충전량·SOC가 아직 결정되지 않았다는 이유만으로 가능한 경로를 임의 제거하지 않는다.

경로 Score 및 Beam 폭에 따른 선별은 Heuristic Ranking으로 분류하고, Exact Prescreening과 혼동하지 않는다.

### 4.3 계통 민감도 기반 우선순위

현재 N1의 FULL 검증점에서 원본 Grid Security를 다시 평가한다.

특히 다음을 반영한다.

- 최대 Thermal Loading 발생 Line/Phase/Slot
- 상위 복수 Critical Grid Row
- MESS 위치별 signed Pch/Pdis/Q 계수
- 이동 전 기존 위치의 계통 기여 상실
- 도착 위치의 혼잡 완화 가능성
- 실제 이동 ETA
- 이동에너지
- 이동 이후 충전 Rebound
- SOC 복원 가능 시간대

혼잡 슬롯 하나만 줄이는 경로를 선택하지 않는다.

특정 슬롯에서 개선되더라도 다른 시간대의 최대 부하율이 상승할 수 있으므로 **전체 96슬롯 최대 목적함수를 후속 MILP에서 다시 계산**한다.

Score는 경로 순위용이며 원본 목적함수를 변경하지 않는다.

### 4.4 경로 유형

다음 실제 물리 경로 후보를 포함한다.

1. 1대 MESS의 단일 이동
2. 이동 후 일정 시간 체류
3. 충전을 위해 다른 위치로 이동한 뒤 필요한 위치에서 방전
4. 2회 이상의 실제 허용 MOVE Arc를 갖는 경로
5. 차량 2대의 협조 위치 변경

최초에는 단일 차량 후보를 우선 평가한다.

다중 이동 및 2대 협조 경로는 계산예산과 초기 결과에 따라 확대한다.

경로 평가 순위가 한 위치나 한 차량에만 편중되지 않도록 Candidate Diversity를 관리한다.

## 5. Stage C — Route-Fixed Exact MILP

이동경로 후보가 생성되면 해당 경로를 고정하고 원본 Exact C3A + Dense MILP를 푼다.

### 수학적 정식화

차량 4대의 선택 경로를 π라고 하면,

`z(π) = min rho_max`

subject to:

- 선택한 Route π 고정
- 4대 Charge Mode 384개 자유
- 전체 Pch/Pdis/Q 자유
- 전체 97개 SOC 경계
- 이동 중 P/Q 금지
- 모든 원본 PCS16
- 전체 Line Thermal/NormalAmps
- 전체 Transformer Security
- 전압 상하한
- SVR11 및 기존 Capacitor Authority
- 고정 AIDC Forecast/PCC
- 원본 초기·종단 SOC
- 원본 96슬롯 Energy Conservation

N1과 차이점은 **Route가 기존 정차 경로가 아니라 새롭게 생성한 이동 경로라는 것**이다.

### 구현 주의

원본 DAG의 Path를 모든 관련 Node-Activity, Arc, continuous Route Flow 및 alias 좌표에 정확하게 변환한다.

원본 검증된 Path Reconstruction을 재사용한다.

선택한 경로를 부분적으로만 고정하거나, 다른 경로가 암묵적으로 혼합되지 않도록 실제 Native 모델을 검증한다.

기존 N1 해가 새로운 이동경로 고정 조건과 모순되면 그대로 MIP Start로 입력하지 않는다.

Solver Start는 신규 고정경로의 조건을 만족한다는 것이 검증된 경우에만 재사용한다.

나머지 충방전 연속 Bounds는 원본과 동일하게 유지한다.

Full MILP의 모든 이동경로를 다시 개방하는 Unrestricted Solve로 바꾸지 않는다.

### Solver 종료 처리

Route-Fixed MILP가 제한된 시간 내 좋은 가능해를 찾으면 원본 FULL Replay를 수행한다.

해당 Restricted MILP의 Solver Gap과 전체 Original FULL Global Gap을 구분한다.

TIME_LIMIT에 도달하더라도 유효한 원본 FULL 가능해가 있으면 UB 후보로 사용할 수 있다.

TIME_LIMIT이며 유효한 가능해가 없으면 해당 경로를 `UNRESOLVED`로 분류한다.

TIME_LIMIT을 INFEASIBLE로 바꾸지 않는다.

## 6. Stage D — 이동성 검증과 UB 갱신

이번에는 다음 두 값을 별도로 보존하라.

**BEST_GLOBAL_UB**

이동 여부와 관계없이 원본 FULL Replay를 통과한 가장 낮은 목적값.

**BEST_MOVING_FEASIBLE_UB**

실제 MOVE Arc가 최소 1개 포함되고 원본 FULL Replay를 통과한 가장 낮은 목적값.

각 이동 후보에 대해 다음 상태를 구분한다.

- DAG_ROUTE_VALID
- ROUTE_FIXED_MILP_OPTIMAL
- ROUTE_FIXED_TIME_LIMIT
- FULL_FEASIBLE_MOVING
- FULL_FEASIBLE_NONMOVING
- FULL_REPLAY_FAIL
- MOVING_UB_IMPROVEMENT
- MOVING_FEASIBLE_BUT_WORSE

다음 조건에서만 BEST_GLOBAL_UB를 변경한다.

`FULL Replay PASS AND candidate_UB < existing_UB`

수치 허용오차 이내의 동등 목적값은 새로운 개선으로 판정하지 않는다.

더 좋은 이동 운전계획을 찾지 못하더라도 기존 N1 FULL 검증 UB를 유지한다.

### 이동성 진단

경로 후보 생성과 최적화가 정상 동작했는지 확인하기 위해, 실제 MOVE Arc가 있는 후보 경로를 고정한 진단용 MILP를 최소 한 번 시험한다.

이 진단은 원본 Objective를 유지한다.

단, 이동을 강제한 진단용 결과를 전체 Proposed의 최적해로 주장하지 않는다.

이동 FULL 가능해를 발견하지 못한 경우 다음을 구분한다.

- 물리적으로 불가능함을 Solver가 증명
- 시간 부족
- 생성한 경로 후보 부족
- FULL 제약 위반
- 탐색은 가능했지만 개선 UB 없음

이동 0회를 곧바로 이동성 무용의 증거로 해석하지 않는다.

## 7. Stage E — K32/K48 기반 Global LB

### 7.1 기존 인증 LB 계승

같은 Source18r과 May01의 기존 K32/K48 인증을 검증하고 사용한다.

`LB_K32 = 0.46497617639758426`

`LB_K48 = 0.46498486997548166`

초기 Global LB는 더 강한 인증값인 K48을 사용한다.

기존 May01의 K32/K48을 이유 없이 다시 계산하지 않는다.

이전 인증 모델·계수·출처와 현재 FULL Problem Identity가 일치하는지 독립 검증한다.

### 7.2 K32/K48의 수학적 계약

K32/K48은 원본 FULL보다 완화된 문제이며,

`FULL feasible projection ⊆ K32/K48 feasible domain`

이 반드시 성립해야 한다.

따라서 K32/K48의 유효한 Gurobi ObjBound는 Original FULL의 Global LB로 사용할 수 있다.

단,

- K32 ObjVal은 Original FULL UB가 아님
- K32 ObjBound만 인증 LB 후보
- Route-Fixed MILP ObjBound는 Original FULL Global LB가 아님

이 구분을 모든 코드와 보고서에서 유지한다.

### 7.3 기존 K32 모델의 한계 인식

기존 K32에는 목적값 `0.4812227124583283`인 축소 정수 가능해가 존재한다.

이 모델을 그대로 풀어서는 현재 UB 0.546162 기준으로 필요한 LB 0.529777에 도달할 수 없다.

따라서 단순 K32 B&B 연장은 금지한다.

### 7.4 조건부 Dynamic Valid Grid Constraint Strengthening

추가 LB 개선이 필요한 경우에만 기존 K32/K48의 인증된 축소 문제를 강화한다.

우선 참고:

- PR211의 K32/K48 위반 원본 Row
- PR214에서 독립 검증됐으나 효과가 미확정인 Fractional Grid Row
- K32/K48 축소 정수해의 원본 FULL 위반 Row
- 기존 Root 분수해의 원본 계통 제약 위반

추가하는 모든 제약은 다음을 만족해야 한다.

1. 원본 FULL에서 유효한 제약
2. Original FULL → Compact 사영 검증
3. Fixed AIDC/Forecast/Correction 항 보존
4. 원본 Phase/Slot/Asset 정합성
5. Binary64 외향 반올림으로 가능영역 보존
6. 기존 행 및 Original Objective 보존
7. 독립 Native Readback PASS

기존 PR211과 같은 제약을 중복 추가하지 않는다.

이미 효과가 없었던 동일 제약 조합을 무조건 반복하지 않는다.

새 강화 모델은 여전히 Original FULL의 유효한 Relaxation이어야 한다.

### LB 업데이트

새 강화 MILP의 실제 Solver ObjBound가 독립 인증을 통과한 경우에만:

`LB_next = max(LB_existing, LB_new_certified)`

Restricted Incumbent ObjVal을 Global LB로 사용하지 않는다.

새 LB가 기존보다 실질적으로 증가하지 않으면 동일한 강화 정책에 계속 시간을 쓰지 않는다.

기준 Material LB Gain은 우선 `0.001`로 설정하고, 그 미만의 증가도 실제 값과 인증 증거는 보존한다.

추가 제약 후보를 유효하게 구성할 수 없으면 LB 신규 Optimize를 건너뛰고 잔여 예산을 Primal 탐색에 배분한다.

3% Gap을 달성하지 못하더라도 허위 인증을 만들지 않는다.

## 8. Stage F — Adaptive Primal–Dual Controller

단순히 경로 20개 평가 후 종료하는 구조로 만들지 않는다.

다음 반복 구조를 구현한다.

```text
INITIALIZE:
    Cold U4/N1 FULL feasible UB
    Inherit verified K32/K48 Global LB

WHILE Native Runtime budget remains:

    GlobalGap = (BestUB - CertifiedLB) / BestUB

    IF GlobalGap <= 0.03:
        STOP with 3% certificate

    Assess:
        recent UB improvement
        recent LB improvement
        remaining runtime
        available route candidates
        valid strengthening candidates

    IF promising route candidates exist:
        Generate/select an original DAG route
        Solve Route-Fixed Exact C3A MILP
        Validate with Original FULL Replay

        IF verified improvement:
            Update BestUB
            Update route-search center and grid scores

    IF qualified LB strengthening exists:
        Solve bounded strengthened K32/K48 MILP
        Verify original-relaxation inclusion
        Verify solver bound

        IF valid:
            Update CertifiedLB

    Avoid duplicated mathematical models
    Avoid repeated failed candidates
    Keep previous verified bounds

END WHILE
```

각 개선 후 Gap을 즉시 다시 계산한다.

Primal과 Dual 중 현재 더 유망한 엔진으로 Native 예산을 전환할 수 있어야 한다.

목적값이 같은 다른 Raw Point를 무의미하게 새 중심점으로 계속 등록하지 않는다.

경로 후보를 모두 사용했다고 판단하는 것은 현재 Beam/Screening 후보 집합의 소진이지, 원본 전체 경로 공간의 완전한 탐색을 뜻하지 않는다.

## 9. 실제 1,800초 Native 예산

총 Native Optimize 누적 상한:

**1,800초**

최초 예산 계획:

| 단계 | 기본 배정 |
|---|---:|
| U4 + N1 Cold Start | 210초 |
| Route-Fixed MILP 기반 UB 탐색 | 1,000초 |
| 조건부 K32/K48 LB 강화 | 300초 |
| Adaptive Reserve | 290초 |
| **합계** | **1,800초** |

각 구간의 조기 종료 후 잔여시간은 Controller가 재배분할 수 있다.

단, 총 Native 누적 상한은 절대 초기화하지 않는다.

실제 사용시간은 Gurobi Runtime으로 측정하고, 모든 Optimize 호출을 포함한다.

권장 개별 Solver 시간:

- U4: 최대 90초
- N1: 최대 150초
- Route-Fixed MILP: 초기 60~120초
- 어려운 유망 Route는 조건부 연장하되 누적 예산 엄수
- 강화 K32/K48: 한 번 최대 300초
- 전체 Unrestricted Full MILP: 실행 금지

전체 1,800초를 강제로 소모할 필요는 없다.

동일한 후보만 남았거나 안전하게 실행할 수 없으면 조기 종료한다.

Native Runtime과 전체 Wall Time은 분리 보고한다.

## 10. 자원 제약

실제 실행 환경은 RAM 약 32GiB이므로 다음을 유지한다.

- Heavy Gurobi Worker 1개
- Gurobi Threads=1
- 다른 Heavy Solver와 병렬 실행 금지
- 원래 B1 Worker 재개 금지
- Windows RAM Reserve 최소 4GiB
- Commit Reserve 최소 6GiB
- 모델 생성 후 관측 메모리 증가에 따른 추가 Reserve
- Solver Nodefile 및 TEMP/TMP 위치 사전 점검
- Source SHA Drift 발생 시 FAIL-CLOSED

기존 실행 중인 외부 프로세스를 강제로 종료하지 않는다.

모델 크기가 비정상적으로 커지거나 메모리 Reserve를 만족하지 못하면 그 후보를 실행하지 않는다.

Source18r의 승인된 수치 정밀도와 Gurobi 설정을 유지한다.

기존 Kappa 및 coefficient range 경고를 숨기지 않는다.
