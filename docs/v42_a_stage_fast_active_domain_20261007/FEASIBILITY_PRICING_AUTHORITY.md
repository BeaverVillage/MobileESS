# Original-native feasibility activation authority

The scientific V2 domain remains unchanged. A restricted active LP's infeasibility does not imply that its physical domain is infeasible. Physical STAY and migration options omitted from the matrix remain indexed in their pools. Reference displacement and grid effect affect activation order only.

`fast_pricing.verify_farkas` independently checks the actual original native CSR matrix, row senses, RHS and variable bounds as exact rationals of their binary64 values. For a row ray lambda, <= rows require lambda >= 0 and >= rows require lambda <= 0. Equality weights are unrestricted. The weighted rows give `(lambda A) x <= lambda b`. Their exact minimum over the original bound box is `L = sum_j min((lambda A)_j * lower_j, (lambda A)_j * upper_j)`. A strictly positive `L - lambda b` proves infeasibility of that captured LP. Nonzero coefficients on the wrong infinite bound fail verification. No small coefficient is discarded and no tolerance manufactures a contradiction.

The live adapter obtains the current model's FarkasDual, verifies that restricted certificate, then prices hard-valid omitted options using explicit native GPU, Runtime, WAN and active-transfer row indices. A directly projected histogram STAY column has coefficient1 on its independently identified cardinality row, negative GPU incidence, negative unchanged Runtime exposure, and unchanged objectives. Its existing native column is independently matched against these coefficients, bounds and objective coordinates. Negative weighted columns can weaken a bound-box contradiction and guide bounded activation. A selected batch is independently replayed before activation. If the restricted ray is not independently valid, the adapter activates no Farkas batch.

For retained singleton mixed event flows and migration blocks, a physical option is a useful hard-valid witness and activation proposal. Its coupling score is explicitly not asserted to be the reduced cost of every native primitive direction. The complete native relaxation permits fractional finish distributions outside the convex hull of physical path columns. Therefore scanning physical options, including an exhaustive STAY scan, cannot certify native full-domain infeasibility or LP closure. The migration scan uses a preregistered bounded canonical compact-block prefix; unscanned options remain lazy.

`NativeExtension` provides a stronger finite certificate. Old row/column indices inject into an actual native extension; shared senses, RHS, coefficient matrix, bounds, variable types and every objective must match exactly. Each new primitive column has an explicit activation-block owner. The old ray is extended by zero on added local rows and every actual new primitive column is checked, including its finite bound capacity. A positive full-extension contradiction proves only that exact finite native extension infeasible. It is never automatically labeled scientific full-domain infeasibility. Row names are insufficient identifiers because native names repeat.

The investigated complete-native alternative is a class-at-a-time local LP oracle. Let the full original model consist of global variables and original local blocks `P_k`, with global coupling `A_0 x_0 + sum_k B_k z_k`. For a compatible global Farkas ray lambda, certify each `min_{z_k in P_k} lambda B_k z_k` using its actual full-native local matrix and bounds, including all fractional source/finish directions. Combine these certified lower bounds with the global bound-box minimum. A sum strictly greater than `lambda b_global` is a valid full-domain contradiction **only after** independent proof that every scientific class, primitive native local direction, coupling coefficient and global row is covered. `verify_local_farkas` verifies a provided native local oracle bound without building the simultaneous full model. A complete production local-block producer/registry and aggregate certificate have not been proved by this implementation.

Current operational classification is **restricted infeasibility may be rescued; native full-domain feasibility closure remains unresolved**. No full-domain infeasibility claim, integer closure or production acceptance follows from witness-only scans. The runner must stop before MILP when the full native LP pricing certificate is unavailable.

No optimizer is called by the verifier or pricing module. All LP solves remain subject to the scoped sequential native execution guard and frozen solver policy. Tests use finite synthetic matrices, including an original-flow fractional finish counterexample; no stress-date optimization is performed by the tests.
