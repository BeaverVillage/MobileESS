## Model construction

Production requests can reuse May01's independently verified preflight physical
cache. The adapter verifies native input and WINDOWS receipts, causal generation,
every scientific DATA value (jobs, resources, bounds, classes and graphs), producer
SHAs, cache bytes and membership. It recomputes all 117 full domain hashes and
compares them against the independent new-run gate. A rejected cache is recorded
and the unchanged original producer runs again. Solver points, bounds and Runtime
are never loaded from the prior run. Every original model and complete block is
rebuilt; the May01 matrix identity is checked before its first Native entry.

`CheckpointMemo` calls the unchanged original function for each unique dependency
tuple. All 202,576 actual May01 start/end conditions and 2,404,927 complete records
match. The observed heavy class (`8676916`, 121 starts, 12 sites) was independently
profiled using fresh Generators: 63.32 seconds versus 53.34 seconds, with identical
STAY/migration blocks and Domain SHA. Original checkpoint computation calls fell
from 353,364 to 179; all 353,364 logical calls still return the original tuples.
Both timings include the same cProfile instrumentation.

The first full fresh model validation completed in 755.93 seconds (12m36s),
including full cache-hash validation and original static verification. Its
698,213-row / 68,026-column reference fingerprint matches the validated original.
All 117 complete blocks, coefficients, constants, variable axes and graphs match;
133,609 STAY and 624,473,721 migration candidates are preserved. The prior cached
preflight completed in 540.46 seconds and had fewer cache-hash checks; the new
validation also ran concurrently with regression checks. This is not claimed as
an improvement over that cached preflight. The old uncached Worker had not
completed preparation when stopped after 39m05s. That observation is a lower
bound on its full preparation time, not a finished benchmark. The first earlier
17-minute preflight failed after domain construction, before matrix/block work,
and must not be compared as an equal-scope full-model benchmark.

Production records fresh DATA, physical cache/domain, active graph, native model,
matrix snapshot/assembly, compact representation and complete block phases.
The read-only monitor keeps elapsed clocks and CPU/RSS samples moving inside
long function calls. A 10-minute stale stage report starts diagnosis, never
automatic termination. A May01 preparation exceeding 1.5 times the matching
validation reference requests investigation; CPU/I/O/counters and read-only
profiles decide whether computation is progressing. These are warning thresholds.

## Native time contract

Only measured Gurobi optimize Runtime is accumulated, including failed calls.
Each call receives `TimeLimit = 5400 - completed_native_runtime`. Construction,
matrix assembly, independent checks and D-day Actual/Fresh AC outside optimize
consume no Native budget. The ledger records nested callback verification costs
separately without subtracting or rewriting Gurobi's actual reported Runtime.
Unknown Runtime quarantines further calls. At exhaustion no more optimize call
is admitted, while non-Native verification may still finish. Wall exceeding
90 minutes is not a budget violation. Existing Gap, Threads, physical constraints,
objective, integer domains and built-in solver heuristic parameters are retained.

B1 runs all 31 dates sequentially. Once all B1 dates are terminal, B2 runs its
independently generated date inputs in three isolated slots. Failed/time-limited
dates are preserved and never automatically retried. The inherited scheduling,
recovery, orphan adoption and three-worker tests pass in the new namespace.
