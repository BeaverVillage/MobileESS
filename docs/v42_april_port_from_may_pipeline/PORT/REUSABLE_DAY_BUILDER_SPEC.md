# Current V42 reusable day builder

`v42_april_port.builder.build_v42_day_input_bundle` accepts a day, separate known snapshot/request/Actual observation channels, frozen Runtime provider, static capacity/rack/network authority, and separate forecast/realized grid inputs. It emits the same `V42_DAY_INPUT_BUNDLE_V1` Planning/Actual schemas for any date. April and May tiny unit fixtures exercise the same code; these fixtures are test data, never scientific April input or May outcomes.

The May blueprint supplies the raw-request canonicalization, Q50 interface, job/state schema, site/rack compatibility, IT/C1/PCC/Q equations and grid/Actual interfaces. The original May bundle is not copied. Numerical May coefficients, job values, reference schedules and results are not inputs. The normalized schema records unresolved bindings explicitly and is not a claim that every day is executable.

Identity is full UID plus aware submission instant normalized to UTC. A positive whole raw `gpus_requested` is the only ported GPU transform. Duplicate/conflicting identities fail closed. Missing GPU remains null with its row retained. Historical `_submission_complete` exclusions are superseded. Existing authoritative positive GPU attributes must agree with the exact raw request. The original request-version/ingestion history is separately unverified in the public retrospective export; a successful UID join does not manufacture that evidence.

Fixed-AEST D-1 cutoff is 18:00, six hours before D-Day. Planning sees only snapshot rows submitted by that cutoff and source request descriptors. It never receives future start/end or unknown arrival identities. Actual post-issue arrivals include the six-hour pre-day carry-in and the D-Day; each request becomes observable at its submission. Actual state endpoints after day end are omitted. These episodes describe observed state, not frozen-plan execution or completion guarantees.

The frozen provider is available before each row event. Batch inference uses the immutable model and request-only features, equivalent to individual row-event inference; no event date, later request, observation or fitted state changes another row prediction. Service is Q50 for PENDING and max(Q50-elapsed,0) for RUNNING, ceiling to 900-second slots. Requested walltime is feature-only. Runtime prediction cardinality is checked. RUNNING Q50 expiry retains hard physical occupancy under PR121 reference/state rules.

Facility capacity and non-additive single-gang rack ceilings use current 780-GPU authority. Source sites are preserved; compatible sites satisfy whole-gang facility and rack bounds. Missing sites use only the preregistered PR121 reference placement rule after all input gates pass. No queue/site decision sees voltage, prices, line loading, Actual results or May results.

`KNOWN_GPU_AUTHORITY_COMPLETE` covers known physical/service rows. `ACTUAL_GPU_AUTHORITY_COMPLETE` covers those same known rows plus all post-cutoff arrivals; an additional arrival-only gate is recorded. Runtime, compatibility, capacity, grid forecast/realized inputs, request-version authority, date-bound CC4 and electrical adapter binding are separate gates. They are not hard-coded to PASS. The present audit creates retained input inventories; it does not generate electrical arrays behind an incomplete GPU gate.

The execution handoff requires complete inputs and PR121 common-reference PASS. B0 retains AIDC and ML Runtime, disables all workload flexibility and MESS, and validates strictly positive served jobs/GPUh/IT/PCC energy/active slots. Planning uses 0.95–1.05 pu; offline forecast AC is diagnostic only. Actual needs independent occupancy/IT/PCC/Q, fresh OpenDSS and the frozen schedule, with zero repairs/reoptimization. No May numeric coefficient or trajectory may fill a missing April adapter. `python -m v42_april_port.audit` builds all 30 April inventories only after the complete May forensic manifests exist.
