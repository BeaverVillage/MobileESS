# Next exact candidate: Dantzig-Wolfe with branch-and-price

This is a design for the next experiment, not an executed decomposition. No restricted-column MIP is presented as a global solution. Activation requires a separate production implementation and verification gate.

The full compact index audit makes the remaining dimension explicit: WAN-start events still have a job x source x destination x time index, even after the checkpoint x transfer-start product is removed. Full-service completion and state variables also replicate across jobs. The exact decomposition candidate is therefore a per-job state-path Dantzig-Wolfe master, with columns generated only when pricing proves they are required. Do not merge similar jobs approximately or remove valid starts, checkpoints, destinations or transfer times.

Keep the unchanged affine grid, CC4 Q10/Q90 service timing, anonymous partitions and reserve headroom in the master. A path column contributes its whole-gang GPU occupancy, exact WAN bytes/active-transfer use, final-site/completion Runtime risk, and intervention costs. The convexity row selects one path for each admitted explicit job. Constant singleton jobs stay constants. Phase I artificial variables may establish the restricted master, but cannot survive physical acceptance.

For each job, dual prices on GPU, WAN, active transfers, Runtime-risk target and convexity rows define an exact reduced-cost path problem. Use the finite source/checkpoint/wait/WAN/restart/destination graph augmented with the selected start/checkpoint phase and consumed-service state where required. Service conservation and checkpoint compatibility cannot be dropped to simplify pricing. A shortest-path dynamic program is valid only after proving acyclicity and that every legacy path is represented; otherwise use the verified compact per-job MILP as the exact pricing oracle. The transfer template is an arc carrying all link/time bytes and restart delay. Completion arcs carry the same issue-adjusted risk coefficients. Grid effects enter pricing through the duals of master linking rows, not through a heuristic site score.

Terminate LP column generation only when every job pricing problem certifies no improving reduced-cost column within a stated dual-feasibility tolerance. Keep primal/dual bounds and pricing tolerances separately. Apply each scientific lexicographic level with its inherited locks; pricing must include those locked master rows. Stabilization may aid convergence but cannot replace an exact final pricing certificate.

LP completeness is not integer completeness. A restricted-column integer solve yields at most an incumbent. A global MILP claim requires branch-and-price with branching constraints incorporated in every future pricing problem, exhaustive node processing or a valid global gap, and independently reconstructed/validated schedules. Candidate branching is on authorized job event decisions; each branch must partition the original path set and preserve exact pricing. Neither old option-index ties nor a finite initial column pool establishes completeness.

Before any May production claim: reproduce all bounded old/compact scientific objectives and paths, test columns introduced only after branching, test infeasible pricing/phase I cases, verify service/GPU/WAN/risk coefficients against the frozen authorities, and measure master construction, pricing, LP convergence, integer bound and memory separately. CL-MC-BD is not activated by this proposal.
