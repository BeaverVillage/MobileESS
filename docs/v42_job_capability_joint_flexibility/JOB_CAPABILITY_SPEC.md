# Job capability and complete options

`v42_job_capability.py` is an isolated ML-independent prototype. It consumes a causal `Job`, a finite provider-issued `ServiceBoundary`, explicit residency/pinning-authorized sites and whole-gang resource limits. It imports no runtime/CC4/semantic model and reads no current-job realized future start/end/runtime/queue fields. The final native service adapter intentionally raises `NATIVE_SERVICE_ADAPTER_NOT_BOUND`; `finalized=False` raises `V42_SERVICE_BOUNDARY_NOT_FINALIZED`.

Eligibility, domain and selected action are distinct:

1. `temporal_candidate` is a QoS/TRAIN proxy gate; no service guarantee is implied. High/urgent/protected fail closed; standby requires an explicit frozen `standby_candidate_authorized` input (default false) and provider window. QoS alone does not promote it. T1 follows PR75 R1 candidate logic with no extra cohort delay cap. T2 requires N≥100, Q25≥900 s and floors Q25 to 900-second slots. It is an empirical proxy, not an SLA or user deadline. No threshold is fitted to a desired share.
2. `build_domain` intersects that gate with explicit allowed starts, includes reference, and constructs full start/site/checkpoint/WAN/restart options. Later starts are generated only within the supplied window/budget. The provider—not this task—must authorize the final service boundary. GPU/rack constraints never split or clip a gang.
3. `executable_domains` forces each option in a **joint** bounded MILP, allowing other movable jobs to move. Thus executable masks require global workload/resource/grid witnesses, not a fixed-other-job capacity heuristic. This exhaustive diagnostic is for canaries, not a scalability claim. A timeout cannot be converted to infeasibility.
4. `capability` on those witnessed options gives TS when reference start and an alternative exist; PS when at some common start at least two initial sites exist; MG when at least one legal checkpoint migration exists. FLEX is their OR; FIX is all false. The selected option, `selected_action`, and `migration_selected` are separate output fields. Historical unresolved masks are null, not FIX.

RUNNING has immutable remaining-service boundary/start/site, and TS/PS false. Causal elapsed_seconds determines physical phase: execution start+1800k, mapped by ceil to 900-second control boundaries, delay in [0,900). Exact current-boundary checkpoints are included. No historical modeled start reconstruction or issue/D00 reset. Missing elapsed disables RUNNING migration only. A carry-in current checkpoint can have a zero-length source segment because its preceding execution is historical, not newly fabricated.

Each admitted option preserves `sum(segment durations)=authorized remaining/total service_slots`. One migration interrupts compute at checkpoint, reserves every link's full payload, then includes one restart interval before exact remaining destination compute. No overlap, duplicate service, second migration, free site switch or future completion read is allowed. `migrations_used=1` disables further migration. Transfer uses the declared inherited deterministic path/maximal-rate law; all possible starts within that finite contract are enumerated. Cross-H service is fully represented and constrained; no post-H electrical security is claimed.

Complete classes: STAY, SHIFT_ONLY, PREPLACE_ONLY, SHIFT_PREPLACE, MIGRATE, SHIFT_MIGRATE, PREPLACE_MIGRATE, SHIFT_PREPLACE_MIGRATE. The old shifted-start migration prohibition is removed **only inside the verified synthetic provider domain**. Existing native prohibition is unchanged until final service and native physical binding pass.

Hard prescreen rejects impossible service windows, GPU/rack, checkpoint, WAN, restart/useful service, and exact duplicates. Immutable background load may be checked safely; other movable jobs are not frozen during pruning. No grid-benefit/topK heuristic or unproven dominance is used. Branch skips and rejected complete options are counted separately in audit semantics. Per-class before/after counts refer to fully constructed options; missing-path/unfinished-transfer branches are separately counted and are not complete options.

FIX singleton choices enter the MILP as constants, preserving full compute and grid load. An unadmitted job raises an explicit separate-backlog requirement; it cannot silently disappear from an admitted workload model. Historical unadmitted records remain in the full local membership ledger.

D-day unknown arrivals are rejected before submit. At submit the currently authorized site-only behavior is preserved: timeshift and checkpoint migration remain disabled with `UNKNOWN_TEMPORAL_MIGRATION_AUTHORITY_MISSING`. This task does not invent a new unknown-job capability contract. Optional semantic-class integration is reserved for a later validated adapter; this implementation does not consume such a field.
