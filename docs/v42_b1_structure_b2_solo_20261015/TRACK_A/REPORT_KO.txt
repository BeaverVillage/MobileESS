1. 가장 구체적으로 확인한 원인

저장된 FAST_B S0 Raw의 최대 절댓값 원본 변수는 column 20436이다.
실제 descriptor의 controls[73][0]이며 이름은 PCC_affine_alias[AIDC01,73]이다.
값은 -1.0368985084808021e17, 원본 하한 -inf / 상한 +inf, Phi 목적 계수는 0이다.
이는 GPU 수요가 1e17이라는 뜻이 아니라 전력망의 PCC affine 보조변수가 수치적으로 멀리 이동한 것이다.

원본 생성 위치는 v42_integration/a_engine.py:68~69이다.
PCC_affine_alias를 자유변수로 만든 다음 PCC_affine_identity로 실제 AIDC 부하 식과 연결한다.
1152개 PCC 변수는 column 19560~20711, 12개 AIDC × 96 slot이다.
이 축은 원본 descriptor와 저장 S0 원본 열 축이 공유하는 global prefix이다.

S0 column 20436의 포함 incident row는 14개이며 모두 <=, 계수는 약 8.63e-12~2.38e-11이다.
restricted row 13110: coefficient=8.626411393243067e-12, RHS=6.847556066577913e-7, NNZ=13.
restricted row 13120: coefficient=9.111854579641918e-12, RHS=6.201584204155704e-7, NNZ=13.
두 행 모두 elastic global row다. 전체 14개 행과 다른 상위 20개 열 정보는 S0_STRUCTURE.json에 있다.
이 열에 걸리는 equality 행이 S0에 하나도 없다. 따라서 원본 PCC_affine_identity equality는 S0에서 생략됐다.
상위 20개 큰 열 모두 PCC alias이고 해당 equality가 포함돼 있지 않음을 독립 확인했다.

따라서 확인된 구조적 문제는 '원본의 자유 보조변수 정의식을 생략한 restricted LP'다.
작은 grid 계수만 남고 실제 부하를 결정하는 identity가 빠진 상태에서 Phi가 원본 변수 크기를 벌점화하지 않는다.
큰 음수 PCC로 일부 포함 grid inequality를 만족하는 방향이 열려 있다. Phi=0이어도 물리 계획을 뜻하지 않는다.
이는 현재 snapshot/Raw에 대한 직접 증거이며, 새로운 Solver 속도 개선 실측이나 full LP infeasibility 증명은 아니다.
PCC identity의 원본 FULL 행 번호와 모든 grid 행의 원본 이름은 경량 descriptor에 저장되어 있지 않아 복구하지 않았다.
restricted row 번호와 원본 FULL row 번호를 혼동하지 않는다.

2. 111.218666의 의미와 실제 Phi

NATIVE03 SOURCE18R_FAST의 Barrier 마지막 Primal Objective 약 111.218665587은 최적화 중 내부 진단값이다.
현재 종료는 TIME_LIMIT(9), SolCount=0, 유효 X/Pi/RC가 없다. 실제 artificial vector와 원본 Phi는 복원할 수 없다.
111개 인공변수나 인증 Phi=111.218666으로 해석하지 않는다. Global LB도 없다.

실제 목적은 v42_a_stage_phase1/core.py:61~85에서 구성한다.
Phi = sum(w_j * a_j), 모든 a_j는 연속형, lower=0, upper=+inf이다.
원본 <= 행에는 -a, >= 행에는 +a, equality에는 +a_plus-a_minus를 추가한다.
가중치는 w=1/2^ceil(log2(max(1,abs(rhs),max(abs(Aij)))))인 양의 정확 dyadic 수다.
이것은 목적의 행별 벌점 정규화이며 원본 A/RHS를 실제로 나누는 행 scaling이 아니다.
local row 및 원본 variable bounds는 hard로 보존하고 명시 global row에만 artificial을 붙인다.
elastic한 전력망 행도 a=0으로 되돌린 원본 물리 한계를 최종 검증해야 한다.

현재 S0에는 14,555 elastic row: equality 5,592 / <= 6,574 / >= 2,389가 있다.
artificial은 20,147개: +1 계수 7,981개 / -1 계수 12,166개이다.
hard local row는 261,414개다.
weight별 artificial 개수: 1:10467, 1/2:1334, 1/4:5832, 1/8:340,
1/16:284, 1/32:254, 1/64:196, 1/524288:96, 1/2097152:1344.
S0_ARTIFICIAL_MAPPING.csv에 artificial column, restricted row, 부호, 정확 weight, 저장 Raw X를 전부 기록했다.

과거 FAST_B_EXTENDED 111.157초 OPTIMAL Raw에서는 20,147개 artificial 값이 모두 정확히 0이다.
Phi도 정확 Fraction 합으로 0이며 S0 원본 포함 행 replay 최대 잔차는 1.1482370609883219e-11이다.
하지만 full compact의 나머지 행은 별도다. 유효한 restricted Phi=0을 전체 feasibility나 DW LB로 승격하지 않는다.

매 반복에서 restricted CSR slicing, elastic hstack, require/verify, solver materialize를 새로 수행한다.

이전 basis가 없으므로 S1은 사실상 새로운 큰 LP다. 기존 row-promotion policy는 최악 19회 후 모든 행으로 승격한다.
행별 한 번씩 add/update하거나 수십 개 행만 너무 짧게 solve하는 전략은 동일한 위험이 있다.
권장 후보는 먼저 definition equality를 항상 보존하고 위반 규모/구조별 묶음을 한 번에 활성화하는 방식이다.

기존 CLASS_COMPRESSION_BUILD_PROFILE은 complete compression/preparation 223.926초와 pricing cache 15.334초를 기록한다.
이 시간을 순수 S0→S1 재구성 비용으로 오기하지 않는다.

7. Native0 우선 개선 후보 및 동치성 검증 계획

후보 A — PCC identity를 모든 restricted LP에서 hard definition으로 보존.
영향: 임의의 free PCC 이동을 막는다. 원본 FULL feasible set는 그대로다.
주의: 중간 restricted elastic Phi 목적/feasible set는 달라지며 과거 Phi trajectory와 동일하다고 하지 않는다.
검증: 원본 identity row의 정확 계수/RHS/열 bounds를 provenance로 등록하고 모든 S에서 포함/hard 여부 검사.
원본 feasible point의 forward inclusion과 Phi=0에서 원본 identity 회복을 정확 유리수로 증명.
예상 비용: 최대 1152개 정의행 보호와 관련 artificial 제외, 수초 수준 감사 가능성. 실측되지 않았다.
Global LB: 이 변경만으로 발급 불가. 전체 omitted row closure와 full-domain pricing/dual correction은 계속 필요하다.

후보 B — PCC affine alias를 exact substitution으로 제거.
영향: 원본 identity p=f(x)를 모든 grid 행/목적/경계에 대입하고 원본 p를 복구하면 원본 feasible set 투영이 같다.
검증: Fraction binary64 계수로 대입 결과를 계산; exact representability 불가능하면 원래 표현 유지.
모든 원본 voltage/line/transformer row를 독립 역상 replay하고 물리 단위를 유지한다.
고정 alias bound를 임의로 추가해 원본 feasible set를 좁히는 방법은 채택하지 않는다.
비용: 1152열+정의행 제거 가능하나 grid 행의 density가 늘 수 있어 fill/메모리 이득은 미확정이다.
현재 수학적 역상·dual certificate 변환 계획이며 Production 구현하지 않았다.

후보 C — 단위/행·열의 정확한 2^k scaling.
Ax<=b에 양의 행 scale, x=D z에 양의 열 scale을 적용하고 bounds/objective/dual를 전부 역변환한다.
정확 power-of-two 표현, overflow/underflow와 계수 소실 검사를 필수로 한다.
원본 absolute tolerance와 engineering unit 기준으로 역상 replay하고 scaled tolerance를 물리 완화로 쓰지 않는다.
LB는 원본 dual/box residual을 원래 단위로 가격화한 별도 정확 또는 outward error correction이 있어야 한다.
weight만 바꾼다고 solver matrix scaling이 된다고 주장하지 않는다.

후보 D — exact duplicate/proportional row, 정의식 및 class 불변 구조 공유.
현재 229 class 검증은 유지하고 UID 권한·QoS receipt를 합치지 않는다.
완전 동일 중복은 row alias와 dual aggregate/split 증명 후 삭제 가능.
비례행/일반 선형종속은 Fraction 관계, RHS/sense 및 bounds까지 증명해야 하며 수치 rank만으로 삭제하지 않는다.
동일 열은 bounds의 Minkowski sum과 objective/모든 row 기여의 정확 일치가 필요하다. 이름만 같은 열을 합치지 않는다.
기존 69,028개 제거를 신규 개선으로 재계상하지 않는다.

후보 E — S0→S1 exact inclusion, 유효 basis 또는 persistent model.
행·열 signature와 artificial mapping을 유지하고 기존 basis가 있으면 새 slack basis의 block-triangular 확장 검사.
현재 1e17 Raw의 단순 PStart는 사용하지 않는다. Basis가 없으면 gain을 미리 주장하지 않는다.
persistent solver 모델은 immutable source/case/row axis와 증분 Native accounting 보장이 선행돼야 한다.
이번 Track A에서는 새 Solver를 실행하지 않아 성능 채택 기준을 충족하지 않는다.

8. Original FULL feasible UB와 DW LB 분리

원본 Integer FULL의 feasible incumbent는 DW Phase I 완료와 독립적으로 얻을 수 있다.
현재 table_v_a.py:186~188도 DW 결과 뒤 solve_original을 호출하고 structural_adapter_failure만 별도 중단한다.
향후 이미 생성된 동일 original model을 사용해 UB 탐색을 먼저 하거나 DW timeout 뒤 남은 Integer 예산으로 진행할 수 있다.
원본 전압/선로/변압기/GPU/QoS/Deadline/SOC/정수 제약을 모두 유지하고 Original FULL replay를 통과해야 한다.
raw incumbent, bounds, objective, source/case SHA를 보존한다. relaxed elastic point를 UB로 만들지 않는다.
DW Global LB는 full row closure + 전체 원본 local domain pricing + dual residual 보정으로 독립 인증한다.
유효 UB만 있고 LB가 없으면 feasible planning과 gap 미인증을 분리해 보고한다.
이번 진단은 이 경로를 새로 실행하거나 B1 예산을 연장하지 않았다.

9. 검증·자원·보존 및 한계
