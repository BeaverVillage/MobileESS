============================================================
0. WHY V12 EXISTS
============================================================

Runtime-vNext11 established that the main remaining problem is not simply
model size, tail-bin resolution, or training-window length.

Observed pre-April temporal drift was large.

Examples:

Fold 1:
    TRAIN runtime median = 56 s
    VALID runtime median = 3624 s

    TRAIN P(T>4h) = 3.99%
    VALID P(T>4h) = 44.31%

Fold 4:
    TRAIN runtime median = 74 s
    CAL median = 25 s
    VALID median = 673 s

    TRAIN P(T>4h) = 9.00%
    VALID P(T>4h) = 22.73%

The relation between archived request descriptors and realized runtime also
changed materially over time.

Simple training-window changes:
    expanding
    180 d
    90 d
    60 d
    30 d

did NOT solve the temporal generalization problem.

The working hypothesis for V12 is:

    request/job descriptors alone do not fully describe the current workload
    regime.

Therefore V12 must add CAUSAL RECENT-REGIME CONTEXT that can be computed using
only jobs whose outcomes were already observable before prediction time.

============================================================
4. NEW FEATURE CLASS: CAUSAL REGIME FEATURES
============================================================

The new feature family must characterize the CURRENT historical runtime /
workload environment at prediction time t.

Every regime feature MUST be calculated only from jobs whose required outcome
was fully known before t.

For example:

    job end_time < t

for completed-runtime statistics.

Never include a job whose runtime completes at or after prediction time.

Never use future jobs.

Never use the current job's eventual outcome.
